# `db/bootstrap/` 集群引导：目录约定与执行顺序约定

本文件是阶段 1 交付物 D-04 的本体。阶段 1 在这一块只交付约定，**五个脚本的内容由阶段 2 交付**，
阶段 2 计划第 3.1 节是这些内容的唯一出处。本文件不复述阶段 2 的任何取值。

## 文件名清单

本目录中允许出现的文件名恰为以下六个，多一个即违反约定：

| 序号 | 文件名 | 承载物 |
|---|---|---|
| 00 | `00_database.sql` | 建库、库级参数、`public` schema 处置 |
| 01 | `01_roles.sql` | 七个功能角色与 24 个属主角色 |
| 02 | `02_cluster_params.sql` | 实例级参数 |
| 03 | `03_role_defaults.sql` | 角色级会话默认值 |
| 04 | `04_pg_hba.fragment` | 主机认证片段，非 SQL |
| — | `README.md` | 本文件 |

阶段 1 曾拟的另外三个引导文件名已按裁定 C-01 整体作废，作废的三个名字见阶段 1 计划第 4.1 节，
本文件不复述——那三个名字按同一裁定不得再出现在任何目录与文档中。

## 执行顺序

按文件名数字前缀升序执行，即 00 → 01 → 02 → 03 → 04。每一步的先后都有约束原因，不是排版顺序：

1. **00 在最前**：后续四步的对象要么建在库内，要么以库为授权范围，库不存在则无处落。
   建库须以 `template0` 为模板并在单独会话中执行，不能与其他语句共事务。
2. **01 在 02 与 03 之前**：02 的连接数上限要把超级用户预留之外的份额分给这些角色，
   03 的 `ALTER ROLE ... SET` 与 04 的认证行都按角色名寻址，角色不存在则语句直接报错。
3. **02 在 03 之前**：02 定的是实例级默认值，03 定的是角色级覆盖值。反过来执行时角色级取值
   仍然生效，但两层的层次关系在脚本上就读不出来，后续排查取值来源要跨文件回溯。
4. **03 在 04 之前**：03 与 04 都只依赖 01。二者之间无技术强序，取此序是因为 03 收尾数据库侧，
   04 之后紧接的是 `pg_hba.conf` 重载这一实例侧动作，把实例侧动作留在最后一步便于安装器分段。
5. **04 在最后且不是 SQL**：它是一段 `pg_hba.conf` 片段，由安装器合入主配置后触发一次重载，
   不经 psql 执行。把它排在末位，是为了让「引导脚本执行完毕」与「新的认证规则开始生效」
   两个时点重合——认证规则先生效而角色未建成，会把安装器自己的后续连接一并拒掉。

## 口令一律不写进本目录

引导文件中不得出现任何口令字面量。口令由安装器从机密库读取后经 `ALTER ROLE ... PASSWORD`
单独注入。该纪律由 `xtask sqlcheck` 规则 SQL-020 强制，规则在阶段 1 实现并配负样例，
被检对象自阶段 2 写入脚本内容起产生。

## 阶段 1 的五个文件里有什么

只有说明性注释，**没有任何可执行语句**。它们不建库、不建角色、不改任何参数。
在阶段 2 写入内容之前，用 psql 执行其中任何一个都不会产生任何数据库对象。

## `xtask sqlcheck` 对本目录的判据

断言本目录中不出现上表六个文件名之外的文件名。该断言是白名单式的否定断言，
与五个 `.sql`／`.fragment` 文件此刻是否已有内容无关。
