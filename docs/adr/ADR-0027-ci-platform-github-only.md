# ADR-0027 CI 平台收敛为 GitHub Actions 单一平台

- 状态：已接受
- 出处：使用方 2026-08-30 逐字裁定「1 只在 github」，关闭 00c F-67 结论三第 3 条登记的 ADR-0005 平台冲突
- 效力来源（F-77 补）：本篇**不在** F-57 总体设计 §1.1 的恰 25 份 precedence 清单内，与 ADR-0005／ADR-0022 一样只经权威登记的 `docs/adr/*` 行取得 `CURRENT_SUBJECT` 效力；该行逐字「反向覆盖 F-57；冲突 ADR 必须另立取代 ADR」，故本篇对 ADR-0005／ADR-0022 决定一的取代成立，但不改变 §1.1 清单本身。**同批已把 ADR-0022 决定一标为被本篇取代**——F-67／F-69 落 ADR-0027 时只扫了 ADR-0005，漏了 ADR-0022 也载有同一条决定。
- 取代范围：只取代 [ADR-0005](ADR-0005-ci-platform.md) **决定一**（「默认 CI 平台取内网自建 Forgejo 加 Woodpecker」）
  与决定三中「Woodpecker 配置」的字面指称。ADR-0005 的其余决定——薄适配器原则、Rust 唯一判定入口、
  Authenticode 生产门禁与开发签名不得发布——**继续有效**，本篇不触碰。
  [ADR-0022](ADR-0022-f57-multi-lane-ci-and-windows-2022-authority.md) 对 ADR-0005 的既有取代范围不变。

## 背景

ADR-0005 决定一选内网自建 Forgejo 加 Woodpecker，理由逐字是「产品面向客户内网私有部署，
源码、离线依赖、制品与签名材料不得因研发设施而被迫出网」。

该决定自作出起就没有落地：仓库内**从来没有 `.woodpecker/` 目录**，唯一存在的流水线定义是
`.github/workflows/ci.yml`（D-07 十一阶段）。这处不一致在 `ci.yml` 头部以「待裁定」形式登记了很久，
其指向的处置说明所在小节后来在一次重写中被删除，指针一度悬空（00c F-67 修复指针并登记该待裁定
**自始无决策归属与期限**）。

## 决定

1. **CI 平台单一取 GitHub Actions**，不再保留 Forgejo/Woodpecker 作为默认或备用平台。
   「两条可选处置」自本篇起收敛为一条，`ci.yml` 头部的「待裁定」注记同批撤销。
2. **执行器一律取自托管 runner**（`runs-on: [self-hosted, …]`）。这是本篇能保住 ADR-0005 原始理由的关键：
   **编排面在 GitHub，构建、离线依赖仓库、制品与签名材料全部留在自有 runner 上**，不因研发设施而出网。
   发布 lane 的 Windows Server 2022 权威节点按 ADR-0022 办理，同样是自托管。
3. **托管 runner 一律不用。** 使用 GitHub 托管执行器会把离线依赖与签名材料带出网，与 ADR-0005
   的原始理由直接冲突；本篇只改平台，不改那条理由。
4. 薄适配器原则不变：YAML 只准备环境、选择 runner、注入已批准的 secret 引用并调用现行判定入口，
   **不在 YAML 里表达任何门禁判定**。判定的唯一真值仍是 Rust 侧入口与 `.github/ci/pipeline-stages.tsv`。

## 理由

源码事实上已经在 GitHub（`origin` 指向 GitHub 远端），`ci.yml` 也已在用自托管 runner——
本篇是把既成事实变成明写的决定，而不是引入一次迁移。选它的代价与另一条路的代价对比：

- **不这么做（维持 ADR-0005 决定一）的代价**：要新建一整套内网 Forgejo 与 Woodpecker 设施并迁移，
  而现行流水线、阶段登记表、两道自检脚本与全部负样例都是围绕 `.github/` 写的；迁移会让这些一并返工，
  换来的只是编排面的位置差别——制品与签名材料在两种方案下都留在自托管 runner 上。
- **这么做的代价，如实记**：**源码托管在 GitHub 上**，这一点与 ADR-0005 原文
  「源码……不得因研发设施而被迫出网」的字面**不一致**。本篇不掩饰该差异：使用方已知源码位置并据此裁定，
  本篇把保护面收缩为**离线依赖、制品与签名材料**三项，由自托管 runner 承担。
  若日后要求源码也不出网，须另立取代 ADR，届时本篇决定一失效、决定二三四可原样保留。

## 后果

1. `.github/workflows/ci.yml` 头部的「待裁定：ADR-0005……」注记撤销，改为指向本篇。
2. ADR-0005 状态行与 `docs/adr/README.md` 记录表同批更新。
3. 全仓其余提及 Woodpecker/Forgejo 的位置（`docs/ci-pipeline.md`、`01-engineering-baseline.md`、
   `14-ops-backup-release.md`、`2026-08-21-f51-development-readiness-freeze.md`、权威登记）
   **本篇不逐处改写**：它们记录的是当时的决定，属历史叙述；本篇在 ADR 层取代该决定即可，
   按 00c 的行号勘误通则「查询以逐字为键，漂移不逐处回改」办理。**唯一必须同批改的是仍在生效的
   `ci.yml` 头注**——它是活的指令而不是历史叙述。
4. **自托管 runner 的存在性仍是外部前置**：本仓查不到任何 runner 注册或预备痕迹
   （`.github/`、`deploy/`、`scripts/` 下命中 0）。本篇选定平台，不解决执行器是否已就位；
   该前置属发布门禁面，不阻塞开发启动。

## 影响范围

- [ADR-0005](ADR-0005-ci-platform.md) 决定一与决定三的「Woodpecker 配置」字面；
- `.github/workflows/ci.yml` 头部注记与 `runs-on` 取值；
- `docs/adr/README.md` 记录表的 ADR-0005 行与本篇新行；
- 00c F-67 结论三第 3 条登记的开放项（本篇关闭它）。
