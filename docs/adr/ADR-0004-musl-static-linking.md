# ADR-0004 构建目标固定 musl 静态链接，基础镜像 scratch

- 状态：已接受
- 出处：阶段 1 计划第 13 节新增决定七；退出条件 12 与 13
- 落地位置：交付形态取值，随 D-11 制品与 D-12 可复现构建证据一并生效

## 背景

产品交付给客户的是可在其内网离线部署的制品。制品的运行环境由客户决定，本方不控制其发行版与 glibc 版本。若二进制动态链接 glibc，制品能否启动取决于目标机上的 glibc 版本是否不低于构建机，这是一条不可在本方流水线上判定的前提。

同时退出条件 13 要求两次独立构建产出完全相同的二进制哈希与镜像 digest。基础镜像每引入一层第三方内容，就多一处不由本方控制的 digest 输入。

## 决定

四条取值：

| 项 | 取值 |
|---|---|
| 构建目标 | `x86_64-unknown-linux-musl`，静态链接 |
| 运行基础镜像 | `scratch` |
| 时区数据 | 经 `chrono-tz` 编译进二进制，不读取目标机的 `/usr/share/zoneinfo` |
| 出网 TLS | 用 `rustls`，信任根以配置指定的 CA 文件为准，即配置键 `egress.ca_bundle_path` |

不使用目标机的任何系统库、时区数据库与证书库。

## 理由

静态链接把「目标机上有什么」从部署前提里整个去掉，代价是二进制体积变大、且不能享受系统库的安全更新——安全更新改由重新构建并发一版制品承担，这与本产品按版本发布升级包的形态本就一致。

`scratch` 基础镜像使镜像内容完全等于本方产出的文件集合，镜像 digest 的输入面因此收敛到本方可控范围，退出条件 13 的判定才有意义。代价是镜像内没有 shell 与任何排障工具，现场排障只能靠日志、指标与另行挂载的工具容器。

时区数据编译进二进制，是因为会计期间与单据日期的解释依赖时区，而目标机的 `tzdata` 版本不受控；同一时间戳在两台机器上被解释成不同的自然日，会直接落到期间归属上。

`rustls` 加显式 CA 文件，是因为 `scratch` 镜像内没有系统证书库，出网 TLS 必须自带信任根；把信任根写成配置键而不是编译进二进制，是为了让客户能在不重新构建的前提下换用自己的内网 CA。

## 后果

正面：一份制品在任意 x86_64 Linux 上行为一致；可复现构建证据的输入面确定。

负面：三处代价已如实记在上面，即体积、无排障工具、安全更新须重新发版。另有一条：musl 的内存分配器在高并发下的表现与 glibc 不同，若阶段 1 性能回归基线（D-15）出现与本决定相关的偏差，须在该基线文件中记录而不是改本决定。

## 当前仓库状态

本 ADR 记的是交付形态取值。截至阶段 1 本轮，仓库内尚无 `.cargo/config.toml` 的目标三元组设定，`chrono-tz` 与 `rustls` 也尚未进入 `[workspace.dependencies]`；`chrono` 已在工作区依赖中并关闭了默认特性。这三项随 D-11 制品与出网客户端骨架落地，落地时不改本 ADR 的取值，只补落点。
