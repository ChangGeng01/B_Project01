# ADR-0018 四具名常驻池与 integration-gateway 零数据库边界

- 状态：部分被 ADR-0019 取代；`integration-gateway` 零数据面边界继续接受并冻结
- 取代说明：[ADR-0019](ADR-0019-f57-runtime-topology-and-measured-connection-budget.md) 只取代本文固定四池和 `37 + 10 + 5 = 52` 产品冻结值；DB/KMS/platform-file/Outbox 全零边界继续有效
- 出处：2026-08-21 数据库架构收口；取代 ADR-0008

## 背景

ADR-0008 曾把 `integ` 与 `rw`、`ro`、`worker`、`ops` 一并登记为五个具名连接池。现行架构已把 `integration-gateway` 收紧为不持有数据库、KMS、平台文件或 Outbox 能力的出网边界；继续保留 `integ` 池会同时制造不存在的连接占用、错误的指标标签值，以及网关可直接接触数据面的误解。

连接预算还需要把正常常驻占用、仅在受控窗口出现的临时占用和不可分配的安全储备明确分开。只写一个峰值会让安全储备被误当成可配置容量，也无法判断迁移或恢复窗口是否越界。

## 决定

一、具名常驻连接池的封闭集合冻结为 `PoolKind { Rw, Ro, Worker, Ops }`。其指标标签逐项映射为 `rw`、`ro`、`worker`、`ops`，不得扩展第五个取值。

二、数据库连接预算冻结为：常驻连接数 `37`；临时、迁移与恢复连接合计不超过 `10`；显式安全储备 `5`；硬峰值 `52`。边界算式为 `37 + 10 + 5 = 52`。安全储备不属于任何具名池，也不得分配给正常运行、迁移或恢复配置。

三、`integration-gateway` 的 `DB/KMS/platform-file/Outbox` 均为 `0`：不创建数据库池或取得数据库连接，不注入 KMS 后端，不读写平台文件，不写入或消费 Outbox。它不得以别名、共享池或临时连接绕过该零边界。

四、ADR-0008 的启动期预算拒启原则继续适用于现行四池与上述分层预算：在创建连接池前完成校验，违反封闭取值域或预算边界时按配置错误退出 78。任何新增 `PoolKind`、提高三层预算或让 `integration-gateway` 获得上述四类能力的变更，都必须以新 ADR 取代本记录并同步重算连接预算。

## 理由

选「四池封闭集合加网关零数据面」而不是保留历史第五池：不采用本决定的代价是配置、指标与实现继续声称网关拥有数据库能力，既浪费连接预算，也扩大出网进程的受攻击面，并使审计无法区分真实依赖与历史占位。

选「37 常驻、10 临时上限、5 安全储备、52 硬峰值」的分层表达，而不是只冻结峰值 52：不分层会让迁移和恢复连接挤占正常常驻连接，或让安全储备被日常配置吃满；故障只会在最需要恢复能力时暴露。

## 后果

正面：连接池枚举、指标标签和容量核算使用同一封闭词表；`integration-gateway` 的数据面依赖可用零值断言机械验证；硬峰值包含明确且不可挪用的安全余量。

负面（如实记录）：`integration-gateway` 不能自行持久化状态、取密钥、落平台文件或投递 Outbox，需要这些能力的流程必须由具有相应边界的内部组件承接。新增池或临时窗口不能只改一处配置，必须重开架构决定并重新核算峰值。

## 影响范围

- `PoolKind`、连接配置文档、启动期 `budget_check` 与连接预算断言；
- `ep_db_pool_connections`、`ep_db_statement_duration_seconds`、`ep_db_tx_retries_total` 的 `pool` 标签取值域；
- `integration-gateway` 的装配边界及 DB、KMS、平台文件、Outbox 零依赖检查；
- 迁移、恢复与认证负载使用的连接峰值口径。
