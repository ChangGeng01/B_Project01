# ADR-0008 五具名连接池与启动预算求和校验违例退 78

- 状态：已接受
- 出处：阶段 2 计划第 7.2 节与裁定 C-04；任务 #11 建池、任务 #14 两应用装配

## 背景

阶段 2 要求两个应用进程共持五个具名连接池 `rw`、`ro`、`worker`、`integ`、`ops`，各池上限之和不得超过 PostgreSQL 侧为本进程划定的连接配额。若池上限配置写错，进程要么在运行期以连接耗尽的方式故障，要么挤占其他七个进程的份额，两种形态都发生在业务流量在场时。

## 决定

一、五个池的名称、用途与默认上限固定为配置模型中的一段，`xtask configdoc` 将其与 `docs/config-reference.md` 双向比对，改名即校验失败。

二、两个应用各持一份 `budget_check`：在 configuring 阶段把五池上限求和，与该进程的配额上限比较，违例逐条返回并由 main 映射为退出码 78（EX_CONFIG）。求和校验在建任何一个池之前执行，违例时不触碰数据库。

三、`pool` 指标标签取值与五池名一一对应（见 `docs/metrics-catalog.md` 第 3.1 节），改池名即同时改指标标签取值域，须走登记变更。

## 理由

选「启动期求和拒启」而不是「运行期限流或告警」：不采用本决定的代价是把配额冲突推迟到运行期——某池打满后其余池的取连接操作排队乃至超时，故障形态是散落的业务错误而不是一个明确的退出码，排障要跨进程对账连接数。启动期拒启使错误只有一种形态：进程没起来，退出码 78，日志逐条列出哪个池超了多少。

选「五池固定命名」而不是「按用途自由命名」：不固定名称则 `pool` 标签取值域开放，指标基数纪律失守，且 ep-migrate 与运维脚本无法按名字引用池。

## 后果

正面：配额冲突在 systemd 拉起阶段即暴露，重试退避策略按其处理配置类失败；五池名成为指标、日志与运维脚本的共同词表。

负面（如实记录）：五池全量建池使最小部署的连接占用是实际需求的两倍以上；`worker` 与 `integ` 池在首版几乎没有流量，其连接是空转的。该代价换的是预算判定的机械性。

## 影响范围

- `apps/core-server/src/wiring/db.rs`、`apps/job-worker/src/wiring/db.rs` 的 `budget_check`；
- 配置模型 `DbCfg` 的池段与 `docs/config-reference.md` 对应键；
- `crates/adapter/db-pg` 的具名池构造与 `ep_db_pool_connections` 标签取值。
