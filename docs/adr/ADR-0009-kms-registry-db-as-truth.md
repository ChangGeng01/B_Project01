# ADR-0009 内置 KMS 内存注册表不持久化，重启后以数据库为基准重建

- 状态：已接受，且明确标注为临时
- 出处：阶段 2 任务 #12、#14 实施期偏离登记第十二条
- 替换方：阶段 3b（Outbox 与密钥状态持久化一并设计）或 HSM 接入

## 背景

内置 KMS 在进程内维护一份已激活密钥域与 KEK 派生材料的内存注册表，A-03 开通、A-04 轮换、A-06 快照都读写它。进程重启后该注册表为空，而数据库里 `key_domains` 与 `data_keys` 的行仍在，密文仍要能被解封、轮换仍要能继续。

## 决定

一、注册表不写任何持久化存储，进程退出即丢弃，不做恢复读取。

二、重启后的正确性以数据库为唯一基准：A-04 轮换不假设注册表在场，经 `generate_detached_data_key` 从库内 KEK 版本直接生成新 DEK 并落库激活；A-06 快照只在注册表存在对应域时同步内存态，不存在则跳过且不报错。

三、注册表缺场不得以错误形态暴露给调用方：凡依赖注册表在场又不在场的路径，一律回落到「以库为准」分支，不产生半完成状态。

## 理由

选「以库为基准」而不是「注册表持久化后重启恢复」：不采用本决定的代价有两条。其一，持久化注册表等于再造一份密钥材料的副本，其保护等级必须与主密钥同级，单机形态下没有第二处可信落点，副本只会扩大暴露面。其二，两份状态（库与注册表）一旦存在即要设计两者的一致性与脑裂处理，阶段 2 没有该预算。以库为基准使密钥状态的真相只有一处，重启是干净的重读而不是恢复。

代价如实记录：注册表内若有尚未落库的进行中状态，重启即断档；A-03 开通半途崩溃后的 PROVISIONING 残留需人工清理（见偏离登记第十一条），阶段 3b 之前不得宣称密钥管理具备故障自愈。

## 后果

正面：密钥状态单源，重启路径无需恢复协议；HSM 接入时注册表整体被硬件后端替换，无持久化格式包袱。

负面（如实记录）：本决定与「KMS 具备高可用」无关，任何文档不得把以库为基准读成高可用承诺。

## 影响范围

- `crates/adapter/kms` 的注册表与 `generate_detached_data_key`；
- `apps/core-server/src/platform/key_domain.rs` 的 A-04、A-06 路径；
- 02 计划 §12 实施期偏离登记第十二条。
