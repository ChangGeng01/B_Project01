## 1. 执行摘要

本产品是一套面向自有企业使用、同时可向其他企业销售的私有化企业运营平台。它覆盖客户、合同、销售、采购、库存、制造、项目、财务、售后，以及一组完整的企业运营、治理、数据与智能模块。

产品不是固定行业 ERP，也不是共享 SaaS。每个客户拥有独立部署、独立数据库集群、独立对象存储、独立密钥、独立许可证、独立升级通道和独立白标客户端。完整业务数据可以部署在客户内网、私有云或公有云 VPC 中，但生产数据、备份、日志、索引和 AI 上下文均限定在中国大陆境内。

平台采用“共享内核 + 可安装模块 + 可替换外部系统”的结构。每个业务领域都可以使用平台原生模块，也可以连接客户已有专业系统。每个“法人 + 业务模块”必须指定唯一主系统、同步方向、字段所有权、冲突规则和对账规则。

核心后端采用 Rust 模块化单体。公网门户、集成网关、工业网关、边缘节点、AI/OCR、分析和插件运行时按信任边界或资源边界独立部署。客户端首选 Tauri 2 + React/TypeScript，安全、领域、同步和离线核心使用 Rust。若四端真机验证未达到门槛，仅将 UI 层切换为 Flutter，Rust 核心保持不变。

正式生产只提供单区域三故障域的最高可用档。低成本的含义是在满足完整范围、安全、兼容和可靠性目标后降低总拥有成本，而不是减少必要的容灾节点、专业验收、真实设备或外部认证。

## 2. 目标、约束与成功定义

### 2.1 产品目标

1. 在 Windows、macOS、iOS、Android 上提供业务能力等价的完整客户端。
2. 跑通客户、报价、合同、订单、采购、库存、生产/项目、财务和售后的端到端闭环。
3. 允许客户通过低代码、自定义数据对象、签名插件、MCP 和连接器扩展系统。
4. 在高保密环境中实现本地 AI、OCR、知识检索和受控自动化。
5. 同一产品同时支持本地机房、私有云和中国境内公有云私有网络。
6. 通过单一核心代码、模块包和自动化白标降低长期维护成本。
7. 为等级保护、密码应用、国产化兼容和第三方安全测评提供控制能力与证据。

### 2.2 固定约束

- 首版仅支持简体中文、人民币和中国标准时间的业务展示。
- 首版不支持多币种、外汇、进出口、报关、信用证或产品内容多语言。
- 每个商业客户独立部署，不使用跨客户共享交易数据库。
- 每个客户内部使用一个逻辑业务数据库，法人通过行级策略、ABAC 和独立密钥域隔离。行级隔离与密钥域是两套必须同时交付的机制，作用层次与跨法人场景见第 7.7 章 与 7.8。
- 生产环境只交付单区域三故障域高可用拓扑。
- 月度可用性目标为 99.95%，可用性的 SLI 口径、豁免规则与发布前判定方式见附录 A。
- 单节点或单故障域失效时，已确认事务的 RPO 为零，RTO 小于 5 分钟。已确认指事务日志已同步复制到至少一个其他故障域，并已向客户端返回成功响应。
- 整个区域失效时，依靠中国大陆境内异地在线不可变备份库恢复，区域级 RTO 不超过 8 小时，区域级 RPO 不超过 30 分钟，该 RPO 以第 13.4 章约定的事务日志归档复制周期不超过 15 分钟为前提；异地离线或气隙副本按第 13.4 章的独立目标判定，不承接区域级 30 分钟 RPO，也不承诺区域级同步 RPO 约为零。
- 所有正式业务模块完成并通过验收后才对外发布完整正式版；内部研发必须分阶段持续集成。
- 不设置固定 GA 日期；正式发布由冻结范围、质量、安全和认证门禁共同决定。
- 源码保存在本地 Git Monorepo；白标客户不维护长期核心代码分支。

### 2.3 “低成本”的定义

低成本采用总拥有成本口径：

- Rust 模块化单体优先，避免无必要的微服务和 Kubernetes。
- 权限、流程、审计、文件、报表、集成和模块机制只建设一次。
- 默认采用宽松许可证的开源组件。
- 商业组件只有在支持离线部署、无强制遥测、许可证可审计且显著减少长期成本时采用。
- 开发和大多数 CI 使用小型环境；定期进入完整 HA 环境进行故障与恢复演练。
- AI 按任务使用最小可用模型；核心交易不依赖 GPU。
- 银行、税务、支付、设备和云连接器先使用模拟器与契约测试，在最终验收期承担真实准入成本。

以下成本不可消除：专业领域人员验收、真实四端设备与工业外设、三可用区验证、HSM/签名设施、第三方渗透和认证、应用商店身份，以及法规规则与连接器的持续维护。

## 3. 产品与商业交付模型

### 3.1 私有化与白标

- 每个客户独立安装、配置、密钥、数据、制品和升级通道。
- 同一核心代码通过品牌配置、签名模块、低代码包和插件产生差异。
- 每个客户可以拥有独立产品名称、Logo、应用标识、证书和应用商店版本。
- 白标构建、签名、灰度和发布必须流水线化。
- 每个客户使用独立签名身份；可由厂商托管专用密钥，也可使用客户自有密钥。
- 签名身份的归属、移动端两条分发路径及其适用条件见第 3.6 章。

### 3.2 许可与知识产权

- 同时支持永久授权与订阅授权。
- 订阅授权的离线生命周期、到期行为与用量计量见第 3.4 章。
- 永久授权与年度维护订阅的边界见第 3.5 章。
- 可以按模块、法人、用户或设备组合许可。
- 可以按法规规则包领域单独许可，规则包的订阅范围、生效版本与到期行为见第 3.5 章。
- 许可证使用数字签名离线验证，不依赖持续联网。
- 核心平台知识产权归厂商。
- 客户业务配置和专用插件归客户。
- 双方共同开发的通用连接器按合同约定。
- 高安全客户可以购买受限源码许可证，用于审计和私有构建，但不得再分发。

### 3.3 扩展市场与支持

- 同时提供企业私有扩展市场与厂商审核市场。
- 所有模块、插件、连接器和模型必须签名、版本锁定并声明权限。
- 厂商可以提供可关闭的轻量部署管理通道，只传输版本、许可证和健康状态，不接触业务数据。
- 故障诊断默认保留在客户本地；诊断包外发前必须脱敏和审批。
- 远程支持支持受控堡垒机和客户代执行两种模式。
- 提供分级技术支持套餐，客户可选择工作时间、7×24、响应时间和现场服务范围。
- 严重漏洞补丁的客户侧安装时限、起算点与延期规则统一由第 21.13 章定义，本章不另行约定；厂商侧的缓解与补丁提供时效见第 17.4 章。
- 支持永久数据可携带：主数据、业务记录、附件、审计、低代码配置和关系映射均可完整导出并附校验清单。
### 3.4 订阅许可生命周期与离线计量

订阅授权在完全离线、且客户已关闭厂商部署管理通道的环境下同样必须可运转。

许可证与状态：

- 订阅许可证是一份签名文件，包含签发日期、到期日期、模块范围、法人范围和用量上限。
- 许可状态分为生效、临期告警、宽限期、受限运行四种，由许可证到期日与本地可信时间判定，全部在本地完成，不需要联网。
- 可信时间取以下三者中的最晚值：许可证签发日期、平台本地许可状态存储中按日落盘的最近一次时间戳、最近一次导入的签名续期或撤销文件的签发时间。该时间戳与用量统计一并按日写入不可篡改审计。
- 本地系统时间早于可信时间时按可信时间判定状态。
- 到期日前 60 天进入临期告警：全部功能可用，管理员在控制台和登录后可见告警。
- 到期日后进入 30 天宽限期：全部功能可用，告警范围扩大到全体用户。
- 宽限期结束后进入受限运行：业务写入、审批、集成出站和自动化任务停止；查询、报表、审计追溯、备份和数据导出保持可用。系统不停机，不删除数据，不锁定数据密钥。
- 受限运行下合规处置通道不可停用：个人信息查询、更正与删除请求的受理和处置，保留期到期销毁，法律保全的设定与解除，以及第 7.9 章要求的删除与保留事件向派生存储的传播、处置清单生成继续运行，其审批链路、双人复核与不可篡改审计一并保持可用，传播目标窗口不因许可状态放宽。
- 合规处置通道产生的写入不计为业务写入，不受许可状态限制；其操作范围限定为上述法定处置事项，不得用于常规业务写入、业务审批或集成出站。
- 进入受限运行时，已提交的 Outbox 消息与在途 Saga 允许继续投递、完成或补偿至终态，之后不再接受新的业务写入与新建自动化任务；未能收敛的条目进入人工任务队列并写入审计，不得静默丢弃。

续期与撤销：

- 续期通过签名续期文件完成，可经文件、移动介质或内网传输任意方式导入；导入成功后状态立即回到生效。
- 撤销通过签名撤销文件导入后立即生效，平台跳过临期告警与宽限期直接进入受限运行。厂商不具备远程强制停机能力；未导入撤销文件时，许可证按自身到期日自然进入受限运行。
- 续期与撤销文件的导入、校验结果和状态迁移写入不可篡改审计。

离线计量与稽核：

- 平台本地持续统计已启用模块、活跃法人数、已激活命名用户数和已注册设备数，按日留存并写入审计。
- 用量超过许可上限时不阻断业务，记录超用事件并在管理控制台显著提示。
- 客户按合同周期（默认每年一次）导出签名用量申报文件提交厂商，文件包含统计口径、统计期间、峰值与均值，并附完整性校验清单。
- 厂商的用量核对在客户现场或经客户审批的诊断包中进行，核对字段限定为许可计量字段，不包含业务数据。

导出不受限：

- 任何许可状态下，3.3 承诺的数据可携带能力不受限制，包括受限运行状态与许可已撤销状态。

### 3.5 永久授权与维护订阅

许可模型为二维结构：软件使用权与更新权分开计价。

- 永久授权覆盖合同约定版本范围内的软件使用权，本身不包含后续法规规则包、安全补丁和连接器更新。
- 法规规则包、安全补丁、连接器更新、版本升级和分级技术支持通过年度维护订阅提供。订阅授权在订阅有效期内默认包含上述维护内容。
- 客户可以按领域订阅规则包，例如只订阅财税规则包或只订阅 HR 规则包；未订阅领域按下述维护到期行为处理。
- 第 18 章的 LTS 3 年维护指厂商对该版本线的维护年限；客户在该期间内实际获取规则包、安全补丁与升级，需持有有效的年度维护订阅或订阅授权。

维护订阅到期后的行为：

- 永久授权部分继续可用：系统不停机，已交付功能保持可用，历史数据访问与导出不受限制。
- 规则冻结在最后一次成功导入的生效版本，平台不再接收新的规则包与安全补丁。
- 依赖法规规则的功能在界面和相关单据上显著标注所用规则版本与生效日期，并提示可能存在申报偏差风险。
- 恢复方式为补订维护订阅并导入期间累积的规则包；导入后按规则包的生效日期与追溯重算机制处理受影响期间。

### 3.6 白标分发路径与签名身份归属

移动端白标交付有两条分发路径，主体归属与责任划分不同：

- 应用商店分发：应用主体与开发者账号归客户所有，厂商以代运维方式完成构建、提交和审核响应。应用名称、图标、隐私说明和资质材料由客户提供并负责，客户对商店条款负责。
- 企业签名/MDM 私有分发：使用客户的企业签名证书或移动设备管理通道分发，仅面向客户内部人员，不进入公开商店。

路径选择与密钥归属：

- 面向客户外部人员的应用（经销商、供应商、终端客户、公众门户配套应用）使用应用商店分发。
- 仅面向客户内部员工的应用默认使用企业签名/MDM 私有分发。
- 厂商托管专用密钥仅用于企业签名/MDM 私有分发与桌面端分发。应用商店分发一律使用客户自有账号与证书，厂商不在自有账号下集中发布多个客户的白标应用。

审核时效与被拒处理：

- 白标发布流水线包含商店政策合规检查门禁，检查项至少包括应用主体与账号归属一致、品牌与标识不冲突、隐私声明完整、资质材料齐备；未通过不得提交商店。
- 第 17.4 章的 24 小时缓解与 72 小时正式补丁时效，在具备企业签名/MDM 通道的应用上以该通道的可交付时间计时。
- 面向外部人员、只有应用商店一条分发路径的应用不存在企业签名/MDM 通道，其时效以服务端或 Web 侧缓解措施的可交付时间计时；缓解措施包括关闭受影响功能开关、收紧网关规则和在外部门户的 Web 形态上发布修复版本。
- 应用商店审核周期不可控，不计入上述两类时效，商店版本按审核结果跟进发布；该计时口径写入交付说明与客户合同。
- 商店审核被拒且两轮修改内无法解决，或审核周期超过 14 个自然日时，按应用受众选择替代形态：仅面向内部人员的应用改由企业签名/MDM 私有分发交付；面向外部人员的应用改由外部门户的 Web 与 PWA 形态承载同一业务能力，或改由客户已通过审核的其他商店主体重新提交。
- 外部人员应用采用 Web 与 PWA 替代形态时，其与原生应用的能力差异在交付说明与客户合同中列明，至少包括推送到达、离线数据范围和设备外设接入三类差异。
- 上述切换记录切换决策、原因、生效范围和后续商店提交计划。

## 4. 总体架构

### 4.1 架构风格

核心交易系统采用可水平复制的 Rust 模块化单体。模块在同一进程中组合部署，但在代码、数据、迁移、权限和契约层严格隔离。

只有满足以下条件的能力独立为服务或进程：

- 存在公网或 DMZ 信任边界。
- 存在工业网络或边缘网络信任边界。
- 需要 GPU、OCR、文档转换或大规模分析等独立资源。
- 故障需要与核心交易隔离。
- 需要单独扩缩或使用受控容器。

### 4.2 逻辑组件

1. 四端客户端
   - Tauri 2 外壳
   - React + TypeScript 界面
   - Rust 领域、安全、离线、同步和设备核心
2. 公网门户
   - 客户、供应商、经销商、员工门户
   - 位于 DMZ，只访问脱敏投影与受控能力 API
3. 核心服务
   - Rust 模块化单体，运行 2 至 3 个无状态副本
   - 领域命令、查询、事务、规则和工作流协调
4. 后台 Worker
   - 通知、报表、文档、对账、批处理、归档
5. 集成网关
   - 银行、税务、支付、签章、Office/WPS、EDI 和外部系统
6. MCP/AI 网关
   - 双向 MCP、模型路由、RAG、OCR、审批和审计
7. 工业与边缘
   - 工业协议网关、现场边缘节点、离线同步
8. 数据与分析
   - 事务数据库、对象存储、搜索、时序、向量、图、分析仓库
9. 运维与安全平面
   - PKI、KMS/HSM、机密库、监控、SIEM、DLP、备份、升级和许可证

### 4.3 Rust workspace 边界

建议的代码边界：

- foundation：稳定 ID、Money、Quantity、Time、错误、安全上下文、事件等最小通用类型。
- platform：策略、元数据、工作流、审计、模块、许可和配置发布。
- contract：每个领域公开的命令、查询、事件和 DTO。
- domain：聚合、值对象、领域服务和业务端口。
- application：用例、事务边界、流程协调和授权调用。
- adapter-db：PostgreSQL、openGauss、达梦、人大金仓、OceanBase。
- adapter：对象存储、KMS、队列、搜索、Office/WPS、外部系统。
- apps：core-server、job-worker、dmz-gateway、edge-node、integration-gateway、plugin-host、analytics-ingest、ai-runtime、ops-agent。

公共 foundation 只能包含真正稳定的通用类型，不能演变为万能共享模块。

## 6. 客户端与用户体验

### 6.1 技术路线

- 首选 Tauri 2 + React/TypeScript。
- Rust 承担认证、安全策略、离线数据库、同步、领域校验和设备能力。
- TypeScript 只承担界面、交互和必须使用 Web 技术的 Office 集成。
- 真机 PoC 必须验证 Windows、macOS、iOS、Android 的性能、无障碍、中文输入、相机、推送、离线加密、生物识别、MDM 和工业外设。
- 若关键门槛未通过，UI 切换为 Flutter，Rust 核心保持不变。
- 门槛的量化通过线、测试设备基线和判定规则见附录 C。

### 6.2 一致性与兼容

- 四端业务能力等价，不要求像素级相同。等价的判定口径与允许差异见本节“平台能力等价定义与豁免清单”。
- 桌面端保持高信息密度；移动端按任务与场景重排。
- 共用设计系统、组件、权限和流程模型。
- 支持浅色、深色、高对比度、全键盘、快捷键、命令面板、批量编辑和连续扫码。
- 无障碍目标为 WCAG AA。
- 客户端支持仍在厂商安全维护期内的操作系统版本。
- 外部门户支持主流浏览器当前版本及前两个主版本。
- 移动端同时支持应用商店与企业签名/MDM 私有分发。
平台能力等价定义与豁免清单：

- 本清单是第 22 章第 5 条“Windows、macOS、iOS、Android 业务能力等价”的唯一判定依据；验收按本清单逐项核对，替代路径成立即视为等价。
- 等价指同一业务对象、同一权限模型、同一流程状态机和同一数据结果在四端一致：同一操作在任一端发起、审批或查询，产生的记录、校验、审计和结果必须相同。
- 等价不要求交互形态、信息密度、外设接入方式和本地实现方式相同。
- 工业外设与专用外设：桌面端直接接入；移动端只支持相机、蓝牙和 NFC 类外设，其余外设由桌面端或边缘节点代理完成。
- 桌面端按第 9.3 章关闭原生插件加载时，扫描仪、标签打印、USB Key、RFID/PDA 等外设能力由边缘节点代理执行；边缘节点不可用时该能力在本设备停用并显式降级，降级范围记入本清单。
- 第 6.1 章真机 PoC 的工业外设项中，蓝牙、NFC 与相机类由移动端直连验证，其余外设由移动端按本清单的代理执行路径验证，不要求直连；逐项通过线见附录 C.2。
- 硬件认证：桌面端支持本机 USB Key 与智能卡；移动端使用硬件绑定、私钥不可导出、抗钓鱼的凭据，第 5.2 章财资支付所述硬件认证在移动端由该类凭据满足。付款、签章和高风险审批的重新认证、双人审批和审计证据要求在四端一致。
- 后台常驻与长时任务：移动端不承诺后台常驻。长时同步、批量导入导出和大文件处理由桌面端或服务端 Worker 执行，移动端只保留可恢复的断点任务。
- 动态扩展代码：移动端不接受任何动态下发的扩展代码，各端扩展形态见第 9.3 章“扩展运行时形态”。
- 离线数据与文件：移动端可按设备存储、网络和安全策略下调离线数据范围与单文件上限，下调后的数值随设备策略下发并可审计。
- 深度编辑场景：像素级打印排版、复杂公式编辑和 CAD 预览测量在移动端提供只读或简化视图，写入操作转桌面端完成。
- 本清单随本规格冻结；新增豁免项必须经产品负责人批准并更新本清单，不得在验收期临时重新定义等价。

### 6.3 离线与设备

- 每台设备拥有独立硬件保护密钥。
- 本地数据库加密并绑定 TPM、Secure Enclave 或 Keystore。
- 离线数据通过用户、设备、密级、记录范围和有效期组成的租约授权。
- 租约到期自动锁定；支持远程撤销和安全清除。
- 检测到 Root、越狱、调试注入或 MDM 不合规时，禁止离线和敏感操作。
- 草稿可字段级合并，附件保留所有版本；财务、付款和合同生效不得离线完成。

### 6.4 Office、文档与设备

- Excel/WPS：导入导出、加载项、实时查询与提交、复杂公式、数据透视、命名区域和条件格式。
- 不执行 VBA、任意宏或第三方 Excel 加载项。
- 文档：模板、在线编辑、批注、修订、版本比较、多人协作和 DOCX 交换。
- PDF/OFD：OCR、批注、可靠遮盖、合并拆分、转换、签名和归档校验。
- CAD：保存原件并提供常见 2D/3D 预览、批注、版本比较和轻量测量；不建设 CAD 建模器。
- 原生设备通过签名插件适配扫描仪、打印机、USB Key、PDA、RFID、NFC、蓝牙标签打印和工业外设；插件的运行时形态、按平台加载方式、权限与审计模型见第 9.3 章“扩展运行时形态”。
- 移动端不接受任何动态下发的扩展代码，只使用随应用包静态签入的设备能力；其余外设按第 6.2 章豁免清单走代理执行路径。
- 条码与标签支持企业规则、GS1、EPC/RFID、UDI、监管码、客户标签和可视化标签设计。

### 6.5 大文件

- 单文件默认上限为 5 GB，可按客户、模块和文件类型调整。
- 使用分片、断点续传、内容哈希去重、带宽限制和边缘缓存。
- 文件发布前必须完成类型识别、恶意内容检查和适用的病毒扫描。

## 7. 数据架构

### 7.1 事务数据

- 每个客户一个独立事务数据库集群。
- 集团内法人共享逻辑数据库，所有法人数据携带稳定法人 ID。
- 在数据库支持时使用数据库原生行级策略；其他数据库使用等价的数据访问策略与认证机制。等价机制的最低要求与判定条件见第 7.7 章，逐库实现状态见第 7.3 章的数据库认证版本组合清单。
- 法人、部门、项目、客户、记录和字段权限由统一安全上下文驱动。
- 每个模块使用独立 schema、数据库角色和迁移目录。
- 时间以 UTC 存储、按中国标准时间展示。
- 金额首版仅支持人民币。

### 7.2 数据所有权与不变量

- MDM 是核心主数据治理入口。
- 库存模块是库存数量账唯一写入者。
- 财务模块是正式会计分录唯一写入者。
- 合同模块拥有合同文本、版本、义务与履约状态。
- 销售订单表达客户需求，不直接修改库存或总账。
- 采购表达供应需求，不直接修改库存或总账。
- 制造通过领料、完工、报废等受控事件影响库存。
- 已过账分录、库存流水、审批证据和审计证据不可覆盖，只能通过更正或冲销追加记录。
- 历史数据导入通过模块迁移接口写入，仍受唯一写入者约束与仅追加约束；迁移批次的标识、授权与对账要求见第 7.10 章。

### 7.3 数据库兼容

- PostgreSQL 为参考实现。
- 正式版还支持 openGauss、达梦、人大金仓和 OceanBase。
- 每个客户部署时只选择一种受支持的核心交易数据库，不在同一客户交易域中混用多个数据库产品。
- 业务功能保持一致，使用公共能力基线与数据库专用优化。
- 每种数据库只支持公开的认证版本组合。
- Oracle、SQL Server 和 MySQL 仅作为外部主系统或数据源。
- 所有核心数据库必须通过同一事务、隔离、迁移、锁、故障和业务不变量认证套件。
- 认证套件必须包含 7.7 定义的法人行级隔离与越权测试集，五种数据库在该测试集上的结果必须一致。
- 数据库认证版本组合清单见下表，逐库标注原生行级策略支持状态、实际采用的隔离机制，以及第 7.8 章中数据文件或表空间级加密的支持粒度。

| 数据库 | 认证版本 | 原生行级策略支持 | 实际隔离机制 | 数据文件或表空间加密粒度 |
|---|---|---|---|---|
| PostgreSQL | 16 | 支持 | 数据库原生行级策略 | 实例级，由存储层或文件系统加密提供 |
| openGauss | 5.0 | 支持 | 数据库原生行级策略 | 法人级，按法人独立表空间透明加密 |
| 达梦 | DM8 | 支持 | 数据库原生行级策略 | 法人级，按法人独立表空间透明加密 |
| 人大金仓 | KingbaseES V8 | 支持 | 数据库原生行级策略 | 法人级，按法人独立表空间透明加密 |
| OceanBase | 4.2 | 不支持 | 第 7.7 章的等价隔离机制 | 实例级，按租户透明加密 |

- 清单中的小版本号与各列取值在阶段 6 前按实际认证结果冻结并随发布证据包发布。实测结果与清单不一致时以实测为准并更新清单，更新后重新执行第 7.7 章的法人越权测试集。
- 使用等价隔离机制的数据库不降低隔离要求，其通过标准与原生行级策略实现一致，判定条件见第 7.7 章。

### 7.4 可定制数据库

- 管理员可以创建自定义对象、字段、关系、校验、索引和视图。
- 支持一对一、一对多和多对多关联核心业务对象。
- 自定义对象自动获得权限、流程、审计、搜索、API、MCP 和报表能力。
- 自定义结构不直接修改核心业务表。
- 默认设置可调整配额。
- 发布前分析索引、容量、性能、安全和迁移影响。
- 配置先在隔离开发/测试空间完成，经自动测试、审批、签名后发布。
- 配置可以导出为声明式包进入 Git，支持差异审查与回退。

### 7.5 文件、分析与归档

- 事务数据库只保存对象 ID、版本、哈希、大小、类型、密级、密钥引用和业务关联。
- 文件正文保存于 S3、云对象存储、NAS、NFS 或 SMB 后端。
- 上传流程：临时对象、哈希/类型校验、病毒/OCR 检查、数据库确认、正式发布。
- 合同、发票、会计档案和审计证据支持 WORM 与法律保全。
- 只有经过认证的不可变后端才能承载 WORM 数据；普通 NAS 只可存放不要求不可变保留的内容。
- Outbox/CDC 将数据送入搜索、时序、向量、图和分析仓库。派生存储的权限执行时机、密级传播、加密与密钥归属、删除与保留期传播规则见第 7.9 章。
- 常规报表不直接压迫主交易数据库。
- 长期数据进入加密归档层，继续受权限、检索、保留和恢复策略控制。
- 归档层不属于第 7.9 章定义的派生存储。来源记录的删除、更正、保留期到期和法律保全状态通过第 7.9 章的同一事件通道传播到归档层，传播目标与第 7.9 章一致，为 15 分钟内完成，超时告警并转人工处理。
- 归档层每次传播生成处置清单，字段与第 7.9 章一致，包含归档存储名称、处理条数、完成时间和校验结果；传播失败进入死信队列。
- 处于 WORM 或法律保全保留义务范围内的归档数据按第 12.4 章的规则继续保留，保留依据、范围和到期重评时间记入处置清单。

### 7.6 数据迁移

- 支持 Excel/CSV、数据库、文件和 API 数据源。
- 迁移流程包含字段映射、清洗、校验、试运行、错误修复、分批迁移和切换。
- 迁移前后执行数量、金额、关系、附件和哈希对账。
- 迁移对账还必须覆盖借贷平衡、库存守恒、期初余额衔接，以及法人 ID、密级和密钥域的赋值校验，明细见第 7.10 章。
- 迁移规则保存为版本化模板，可重复演练。
- 历史系统只读冻结、增量追平和正式切换必须产生审计证据。

### 7.7 法人行级隔离机制

法人隔离由统一安全上下文驱动。安全上下文包含客户、法人、用户、设备、角色、密级和数据范围，由核心服务在每次请求开始时建立。调用方可以按第 8 章的命令契约声明目标法人，服务端必须对照该用户与设备的授权法人集合校验后才写入安全上下文，不得直接采信调用方声明的法人标识；校验失败直接拒绝。

两类数据库共同适用的最低要求：

- 模块、插件、低代码、报表和 MCP 工具不得获得事务业务库的直连连接；高级只读 SQL 按第 9.1 章只能在分析副本或沙箱中运行。
- 直连数据库的高权限操作只能通过破窗流程发起并独立审计。
- 连接归还连接池前清除会话中的安全上下文，防止上下文残留到下一请求。
- 数据库账号按模块与用途最小授权，应用账号不具备关闭或修改隔离机制的权限。

数据库支持原生行级策略时：

- 安全上下文在连接取用时写入会话变量，行级策略以该变量为唯一判据。
- 应用数据库账号不具备绕过行级策略的权限。

数据库不支持原生行级策略时，使用等价隔离机制，最低要求如下：

- 所有业务读写只能经过统一数据访问层，由统一查询构造器强制注入法人谓词，模块代码不得自行拼接法人条件。
- 缺少法人谓词的查询在数据访问层直接拒绝，不允许默认放行。
- 跨法人聚合查询只能由显式声明跨法人授权的查询发起，授权范围写入审计。

等价性判定条件：

- 存在一套统一的法人越权测试集，覆盖读取、写入、更新、删除、聚合、排序、报表投影和错误信息泄漏。
- 该测试集在原生行级策略实现与等价机制实现上的结果必须完全一致，不出现越权读取、越权写入或跨法人聚合泄漏。
- 新增模块、新增自定义对象和新增查询入口在发布前必须通过该测试集。
- 测试集属于 7.3 数据库认证套件的必测项。

### 7.8 密钥域

密钥域是数据加密密钥的划分单位，用于限定密钥的归属、轮换范围和销毁范围。密钥域不承担访问控制判定；法人、记录、字段和密级的访问控制由 7.7 的行级隔离与 ABAC 承担。两套机制同时生效，互不替代。

- 每个客户拥有独立根密钥。
- 每个法人在客户根密钥下拥有独立数据加密密钥域，属于强制交付项。
- 密级、附件和归档可以在法人密钥域内使用子密钥，不跨法人共享。
- 事务数据库使用信封加密：行内敏感字段按法人密钥域与密级使用字段级密钥，属于强制项。
- 数据文件或表空间级加密按数据库能力提供，粒度可以是实例级或法人级，逐库取值见第 7.3 章的数据库认证版本组合清单，不作跨库统一承诺。
- 集团共享密钥域用于已授权共享的数据，其访问同样受 7.7 的行级隔离与 ABAC 控制。

跨法人场景的处理规则：

- 跨法人查询先按第 7.7 章 过滤法人范围，再解密结果中的敏感字段；服务端只在显式跨法人授权范围内使用相关法人的密钥，授权范围与密钥使用记录写入审计。
- 跨法人交易在双方法人各自生成独立单据，各自写入本法人密钥域，通过关联编号建立对应关系。
- MDM 跨法人分发的主数据写入集团共享密钥域，法人专有敏感字段不进入共享部分。
- 财务合并在合并账簿中生成新记录并写入集团共享密钥域；下钻到法人明细仍按该法人的权限与密钥授权访问。
- 法人密钥销毁只影响该法人密钥域内的数据，不得导致其他法人数据或集团共享数据不可读。
- 密钥销毁属于删除手段，不得用于规避保留义务。密钥销毁与 WORM 或法律保全冲突时，按第 12.4 章 的规则由适用法律与保留策略决定，并保留可验证处置证据。

### 7.9 派生存储安全继承

派生存储包括搜索索引、时序库、向量库、知识图谱、分析副本和分析仓库。派生存储不重新定义权限，只继承来源数据的安全属性。

- 每条派生记录携带来源对象 ID、版本、法人 ID、密级和数据范围标签，由 Outbox/CDC 事件统一写入；缺少上述标签的事件不得写入派生存储。
- 权限执行时机：索引期只做法人分区与标签写入，不做用户级裁剪；查询期由统一安全上下文按法人、记录、字段和密级过滤。
- 过滤在派生存储前置的查询服务中完成，调用方、插件和低代码不得直接访问派生存储端点。
- 9.1 的高级只读 SQL 在分析副本或沙箱中运行时，必须经同一解析与权限重写层完成本节要求的法人、密级和字段过滤，视为经前置查询服务访问；除此之外不存在其他直连派生存储的路径。
- 密级传播：派生记录的密级不低于来源记录；一条派生记录聚合多条来源时取其中最高密级。
- 字段级控制：无权字段不进入返回结果；不得通过排序、聚合、分面计数或相似度打分间接暴露无权数据。全文与向量检索先按法人、密级和数据范围过滤候选集，再计算相关度。
- 加密与密钥归属：与事务数据库同构的分析副本沿用第 7.8 章的事务数据库加密口径，不另行要求按法人分区；搜索索引、时序库、向量库、知识图谱和分析仓库等独立构建的派生存储按后端能力提供分区级加密，逐后端在本节“派生存储后端认证清单”中标注，不作跨后端统一承诺；集团级分析仓库只允许存放集团共享密钥域数据，或已按规则脱敏与聚合后的数据。
- 删除与保留传播：来源记录的删除、更正、保留期到期和法律保全状态通过同一事件通道传播到全部派生存储，传播目标为 15 分钟内完成，超时告警并转人工处理。
- 每次传播生成处置清单，包含派生存储名称、处理条数、完成时间和校验结果；传播失败进入死信队列。处于法律保全或 WORM 保留义务范围内的记录按第 12.4 章 的规则继续保留，并在处置清单中记录保留依据。
- 失效重建：派生存储可以按法人从来源数据完整重建；重建期间该分区停止对外服务，重建后重放待处理的删除与保留事件，并与来源做条数一致性校验和哈希抽样对账。
- 权限模型、密级规则或分区规则变更时，受影响范围必须在变更生效前完成重建或重新打标。
- 派生存储越权测试与删除传播验证作为独立测试项纳入发布门禁。

派生存储后端认证清单：

- 清单逐后端标注产品与版本、按法人分区支持状态、加密粒度和采用的等价手段，随第 17.5 章认证矩阵一并冻结与发布。
- 支持按分区使用客户托管密钥的后端，各分区使用所属法人密钥域的数据加密密钥。
- 不支持按分区密钥的后端，采用下列等价手段之一并在清单中标注：按法人使用独立实例或独立集群承载，或在写入派生存储前对敏感字段执行所属法人密钥域下的信封加密。
- 未列入清单的后端不得用于承载敏感密级的派生数据。
- 第 16 章扩展策略允许的后端切换必须先完成本清单登记与标注，未登记的后端不得进入生产。

### 7.10 历史数据导入与迁移对账

历史数据导入使用受控写入通道，仍受 7.2 的唯一写入者约束与仅追加约束。迁移窗口内唯一放宽的是允许按批次批量写入历史期间数据，其余约束不放宽。

- 受唯一写入者约束的数据只能经对应模块提供的迁移接口写入，迁移工具不得直写业务表。
- 每次导入必须声明迁移批次，内容包括批次编号、来源系统、法人、账簿或仓库范围、授权人和时间窗口。
- 期初余额与历史凭证写入专用迁移账簿，或以迁移批次标识标记，与切换后的正常业务数据可区分、可追溯、可整批冲销。
- 导入授权由数据责任人与对应模块责任人共同审批，审批记录、批次定义和执行结果写入审计。
- 迁移窗口关闭后迁移接口自动停用，再次开启需要重新审批。
- 导入后的数据同样不可覆盖，发现错误只能通过更正或冲销追加记录。
- 批量写入不豁免权限校验、审计记录和不变量校验。

迁移对账清单：

- 借贷平衡：每个迁移批次导入后，按账簿与期间统计的借贷合计相等。
- 库存守恒：期初数量加导入流水等于迁移后库存结存，按仓库、物料、批次逐项核对。
- 期初余额衔接：历史系统期末余额与平台期初余额按科目、辅助核算、仓库和批次逐项一致。
- 数量、金额、关系、附件和哈希按第 7.6 章 的规则对账。
- 法人 ID、密级、密钥域和保留期在映射表中显式赋值，不允许默认填充；校验不通过的记录进入错误队列，不进入正式数据。

强制不变量的验收范围包含迁移批次数据。借贷平衡、库存守恒和期初余额衔接的差异必须为零，不设容差；对账未通过时不得执行正式切换。

## 8. 黄金业务闭环

1. CRM 接收线索，经商机、资质与风险检查进入 CPQ。
2. CPQ 根据产品配置、成本、价格、折扣和审批规则生成报价。
3. 报价确认后进入 CLM，完成条款审查、签章、履约义务和收付款计划。
4. 合同生效后生成销售订单；OMS 根据 ATP/CTP、仓库、产能和规则拆分履约。
5. 需求进入采购、MRP、生产或项目计划。
6. 收货、生产完工和退货必须经过 WMS/QMS。
7. 发货、签收、订阅用量或项目里程碑触发计费、开票和收入确认。
8. 财务引擎将经过验证的业务事件转为应收、应付、成本和总账凭证。
9. 收付款、银行对账、税务和结账完成财务闭环。
10. 设备、产品和合同权益进入售后、保修、现场服务和客户门户。

事务边界：

- 单一领域内部使用数据库 ACID 事务。
- 跨领域流程使用 Outbox + 持久化工作流/Saga。
- 不使用跨数据库分布式事务。
- 每条命令携带客户、法人、用户、设备、权限、幂等键和关联链路。
- 长流程失败时执行重试、补偿或人工任务。
- 外部系统只能通过集成网关提交版本化命令。
- AI、OCR 和 MCP 只能生成建议或受控命令。

## 9. 低代码、规则与模块发布

### 9.1 低代码能力

- 自定义对象、表单布局、列表列、首页、菜单和看板。
- 可视化审批、并行会签、定时器、子流程、SLA、补偿和人工任务。
- 声明式规则表达式与版本化规则。
- 复杂计算调用受限 WASM 函数。
- 不允许任意 JavaScript、Python、Shell 或本机程序进入核心环境。
- 高级只读 SQL 只能在分析副本或沙箱中运行，并受解析、权限重写、超时和结果限量控制。
- 默认使用内置 Rust 持久化流程引擎；大型客户可通过适配层连接外部流程编排平台。引擎必须满足本节“流程引擎语义要求”，并通过第 17.2 章流程引擎认证套件。
- 本地 AI 可以生成流程或规则草稿，但必须经过模拟、权限检查、审批和管理员发布。
流程引擎语义要求：

- 流程实例状态、任务、定时器和补偿记录持久化在事务数据库中，与业务状态和 Outbox 写入使用同一数据库事务，或由 Outbox 保证最终一致。
- 步骤执行按至少一次投递设计，每个步骤携带幂等键；重复投递不得产生重复业务效果、重复事件或重复审计记录。
- 定时器、SLA 和重试在第 13.1 章的 2 至 3 个核心副本下必须唯一触发，使用数据库租约或独立选主实现；副本重启、滚动升级和网络分区期间不得漏触发或多触发。
- 补偿按已完成步骤逆序执行，允许部分失败；补偿失败的实例进入人工任务队列并告警，不得静默结束。
- 流程定义版本化，运行中的实例继续使用发起时的版本；版本迁移必须显式声明、可模拟并可回退。
- 单实例最长运行期、最大步骤数、最大并行分支和实例保留期由配置约束，超限进入人工处理。
- 引擎自身的状态变化写入审计，可按实例查询完整执行轨迹与补偿轨迹。
- 财务过账、付款、开票和合同生效相关流程不得依赖仅存在于内存的状态。

不达标预案：

- 引擎认证项见第 17.2 章；认证未通过时，依赖跨域流程的阶段验收不得放行。
- 若内置引擎在认证中未达标，跨域一致性改为通过适配层运行在外部流程编排平台上；此时适配层为正式交付项而非可选项，低代码流程模型、公开契约、权限模型和审计要求保持不变。
- 外部编排平台的流程实例状态保存在该平台自带的状态存储中，豁免本节的同事务写入要求；业务状态、Outbox 与审计仍写入同一数据库事务，流程状态与业务状态之间由 Outbox 与步骤幂等键保证最终一致。
- 切换外部流程编排平台不改变本规格的模块目录与第 20 章排除项；该平台作为新增组件纳入第 13.1 章正式拓扑，按第 13.2 章部署适配交付，并必须满足第 2.3 章对商业组件的全部采用条件。
- 该平台必须覆盖第 17.5 章认证矩阵冻结的全部基线组合；无法覆盖时在触发本预案的同时收窄基线组合，收窄结论与认证矩阵变更由产品负责人批准并写入验收证据。
- 该平台按第 13.3 章单故障域失效目标交付：已确认的流程实例状态 RPO 为零，RTO 小于 5 分钟；不满足时该平台只承担无状态编排调度，实例状态以事务数据库中的流程记录与 Outbox 为准。

### 9.2 配置发布

- 开发、测试和生产完全隔离。
- 非生产数据使用合成数据或生产数据脱敏副本。
- 配置进入 Git，经过差异审查、自动测试、审批和签名。
- 核心升级前自动建立脱敏验证环境，运行模块、插件、配置、数据库和接口兼容测试。
- 验证失败时阻止生产升级。

### 9.3 模块与插件

- 普通扩展使用签名 WASM Component，SDK 以 Rust 为主。
- 任何能生成标准 WASM Component 的语言均可使用。
- AI、OCR、工业协议等重型能力可使用隔离容器。
- 插件默认没有网络、文件、密钥或业务数据权限。
- 插件必须声明能力、域名、端口、对象、字段和资源限额。
- 权限经审批后按最小权限授予。
- 插件不能直接访问核心数据库，也不能读取明文机密。
扩展运行时形态：

- 签名、版本锁定、能力声明、最小权限授予和审计要求对以下形态一致，差异只在宿主与加载方式。
- 服务端 WASM 插件：运行在 plugin-host 中的签名 WASM Component，默认无网络、文件、密钥和业务数据权限，为普通扩展的默认形态。
- 服务端隔离容器：AI、OCR、工业协议等重型能力使用签名 OCI 容器，网络、挂载和资源限额按声明限定，只通过受控接口与核心交互。
- 桌面端签名原生插件：Windows 与 macOS 客户端可动态加载访问本机设备接口的签名原生插件，用于扫描仪、打印机、USB Key、PDA、RFID、蓝牙标签打印和工业外设。
- 移动端：iOS 与 Android 不接受任何动态下发的扩展代码，设备能力只能来自随应用包静态签入的能力集；移动端涉及的扩展逻辑在服务端 plugin-host 中执行，移动端只消费其结果。

桌面端原生插件的安全边界：

- 插件包由厂商或客户签名；签名主体、版本、哈希和能力清单写入本地插件登记表，验签失败或清单不匹配时不加载。
- 插件必须声明设备类型、接口、进程权限、文件路径和资源限额；未声明的能力在宿主侧拒绝。
- 插件运行在独立子进程中，通过受限 IPC 与客户端核心通信，不共享客户端进程内存、离线数据库密钥和会话令牌。
- 插件不获得业务数据读写权限，只处理由核心传入的最小必要数据，并按密级执行脱敏与日志限制。
- 插件崩溃、超时或越权调用只影响该子进程，宿主记录事件并按策略停用该插件。
- 插件加载、能力授予、设备访问和异常退出写入客户端审计，并随设备健康状态上报。
- 客户可在设备策略中关闭原生插件加载；关闭后本机相关外设能力按第 6.2 章豁免清单由边缘节点代理执行，边缘节点不可用时该能力在本设备停用并显式降级。
- 本形态的子进程隔离、签名与能力清单与第 21.7 章的沙箱控制等效，属于该节所述控制手段的组成部分。
- 移动端所需的原生外设操作由桌面端或边缘节点代理执行；移动端新增设备能力只能通过应用版本发布，纳入客户端分批发布与强制安全更新流程。

## 10. 集成平台

### 10.1 支持协议

- REST、OpenAPI、批量 API、Webhook、业务事件
- CSV、Excel、XML
- EDI、SFTP、AS2
- 消息队列
- 双向 MCP

### 10.2 主系统规则

- 每个“法人 + 模块”指定唯一主系统。
- 字段所有权、同步方向、数据范围和转换规则必须显式定义。
- 内置和外部系统不能同时成为同一字段的主系统。
- 安全冲突按版本与字段所有权自动处理。
- 无法安全判断的冲突进入隔离队列，由数据责任人处理。

### 10.3 可靠性与机密

- 所有写入使用幂等键。
- 支持退避重试、超时、熔断、死信、人工修复、重放和对账。
- 密码、证书和 API Key 存入内置机密库或外部 Vault/KMS/HSM。
- 插件只能请求使用机密，不能读取或显示明文。
- API、MCP 和插件 SDK 支持当前版本及前两个主版本。
- 低代码对象与流程可以发布为受治理 API。

### 10.4 连接器范围

包括但不限于 AD/LDAP/OIDC、MDM/EDR、Office/WPS、邮件/日历、银行、数电发票、税务、支付、电子签章、物流、TMS、HR/HCM、PLM、MES、SCADA、IoT、GIS、BI、ECM、CTI、商旅和外部风险数据。

## 11. MCP 与本地 AI

### 11.1 双向 MCP

- 使用官方 Rust SDK 实现 MCP Client 与 Server。
- 所有 MCP 流量经过 Rust MCP/AI 网关。
- 数据库、模型、OCR、向量库不直接暴露 MCP。
- MCP 身份映射到真实用户、设备、法人、角色和认证强度。
- 每次工具调用重新检查记录、字段和数据范围权限。
- 外部 MCP 返回内容视为不可信数据。
- MCP 协议封装在适配层，不进入领域模型。

### 11.2 风险分级

- L0：查询、搜索、摘要，可自动执行。
- L1：报价草稿、凭证模拟、采购建议，可自动生成但不正式生效。
- L2：普通业务新增或修改，需要明确确认、幂等和审计。
- L3：合同生效、付款、开票、过账、结账、敏感导出，只能创建待审批命令。

### 11.3 本地模型

- Rust 负责权限、编排、RAG 过滤、结构化校验、审批和审计。
- 推理与 OCR 在隔离服务运行。
- 支持 CPU、NVIDIA、AMD、Apple Silicon 和企业内部 AI 集群。
- 私有模型仓库记录来源、许可证、签名、哈希、SBOM、评测和适用任务。
- 模型、提示模板和知识索引版本化，可灰度与回退。
- OCR 使用字段级置信度；金额、税号、账户、日期和条款必须复核。
- AI 保存来源、模型版本、置信度、结构化结果和人工确认，不保存内部思维过程。
- AI 对话、提示词和输出按任务与密级配置保存、脱敏、加密和保留期；敏感会话可只保留摘要与证据哈希。
- 企业知识检索同时支持关键词、向量和知识图谱，严格继承原文档权限并返回可验证引用。
- 外部门户 AI 客服只能访问公开内容或当前用户已授权数据，支持敏感问题拦截和转人工。
- 客户数据只可在客户本地、明确审批后训练；派生模型归客户。
- AI、OCR、搜索或知识平台故障时降级为人工流程，不能阻塞核心交易。

## 12. 身份、安全与隐私

### 12.1 身份与认证

- 员工接入 AD/LDAP/OIDC。
- 保留受控应急本地账号。
- 外部用户支持邀请、自助注册和企业身份联合。
- 支持密码、TOTP、Passkey、生物识别、设备证书、智能卡和 USB Key。
- 高风险审批、付款、签章和导出必须重新认证。
- 高风险操作将认证方式、待签内容摘要、时间与设备写入审计证据。
- 用户、服务、设备、边缘节点和插件具有独立工作负载身份。

### 12.2 授权

- RBAC + ABAC。
- 支持法人、部门、项目、客户、记录和字段级权限。
- 支持密级、职责分离、临时授权、审批授权、代理和值班组。
- 策略默认拒绝，并提供策略模拟和影响分析。
- 不设置全能超级管理员。
- 系统、数据、安全、审计和密钥管理员职责分离。
- 破窗权限必须限时、强认证、实时告警并由独立人员复核。

### 12.3 加密与密钥

- 传输使用 TLS/mTLS。
- 存储使用信封加密。
- 国际算法与 SM2、SM3、SM4、国密 TLS 通过密码提供者切换。
- 支持内置 KMS、云 KMS、HSM、国密设备和客户自带密钥。
- 每个法人使用独立数据加密密钥域；密级可在法人密钥域内进一步划分子密钥域。
- 密钥域只界定密钥归属、轮换和销毁范围，不承担访问控制判定；跨法人交易、共享主数据、财务合并和派生存储的密钥域规则见第 7.8 章 与 7.9。
- 内部服务、设备、边缘和插件同样采用零信任身份与 mTLS。
- 内置证书生命周期管理，支持签发、轮换、吊销、到期告警并可连接企业 CA/PKI。

### 12.4 DLP 与隐私

- 规则与本地 AI 辅助识别数据密级。
- 按策略执行脱敏、水印、导出、打印、剪贴板、分享和文件失效控制。
- 支持文件指纹、接收人绑定、打开审计和泄漏追踪。
- 个人信息执行告知同意、目的限制、最小化、保留、查询、更正、删除、撤回和影响评估。
- 更正、删除和保留期到期处置必须按第 7.9 章传播到搜索、时序、向量、图和分析仓库等派生存储，并按第 7.5 章传播到归档层，两处传播均生成可验证的处置清单。
- 除按本章保留策略与法律保全规则必须继续保留的部分外，全部传播完成前请求不得标记为完成；继续保留的部分在处置清单中记录保留依据、范围和到期重评时间。
- WORM/法律保全与删除请求冲突时，由适用法律与保留策略决定，并保留可验证处置证据。
- 到期销毁必须经过复核与双人审批，并生成可验证销毁证明。
- 人脸、指纹等生物特征默认保留在设备或专业核验系统中，平台只保存必要的核验结果与证据引用。
- 系统不保存完整银行卡号、CVV、支付密码等支付认证数据，只保存令牌、脱敏标识和交易结果。

### 12.5 审计

- 业务变更与审计事件在同一事务记录。
- 高权限数据库操作独立审计。
- 审计事件建立哈希链并签名。
- 证据写入独立 WORM 存储。
- 普通运行日志与业务审计分离。
- 日志禁止保存令牌、密钥和无必要敏感明文。

## 13. 部署、高可用与容灾

### 13.1 正式拓扑

- 单区域三个独立故障域。
- 员工入口使用 VPN 或零信任访问网关；公网门户入口使用 WAF/API 网关并进入 DMZ。
- 双入口负载均衡或 VIP。
- 2 至 3 个无状态 Rust 核心副本。
- 三节点事务数据库 HA 集群。
- 高可用对象存储或云对象存储。
- 独立 Worker、集成网关、MCP/AI 网关和边缘接入。
- 同区域快速恢复库。
- 中国大陆境内异地在线不可变备份库，承接区域级 RTO 与 RPO 目标。
- 中国大陆境内异地离线或气隙副本，作为额外防护层级，不承接区域级 30 分钟 RPO。

三个节点必须位于独立故障域，不能只是同一物理宿主上的三台虚拟机。

### 13.2 部署适配

- 标准 OCI 容器。
- Linux/国产 Linux 是核心与数据库默认平台。
- Windows Server 用于边缘、连接器和特定应用节点。
- 普通服务器使用轻量容器编排。
- 已有成熟 Kubernetes 时使用 Kubernetes 适配包。
- 支持本地机房、私有云、阿里云、腾讯云、华为云和通用公有云。
- 支持自建组件与云托管组件互换。
- 核心只依赖开放接口，避免云厂商锁定。

### 13.3 可用性目标

- 月度运行 SLO：99.95%，按附录 A 定义的 SLI 口径逐月度量并出具报告。
- 发布前不使用运行期月度数值判定可用性，改用附录 A 规定的预生产实测门槛。
- 单节点或单故障域失效：已确认事务 RPO 为零，RTO 小于 5 分钟。
- 区域灾难：使用中国大陆境内异地在线不可变备份库恢复，RTO 不超过 8 小时，RPO 不超过 30 分钟，前提是第 13.4 章的事务日志归档复制周期不超过 15 分钟；从异地离线或气隙副本恢复时按第 13.4 章的独立目标判定。
- AI、OCR、搜索和分析允许降级；相关降级不计入可用性统计，核心交易不受阻塞。
- 所有目标以真实切换、恢复和容量测试结果验收，演练场景与判定标准见附录 A。

### 13.4 备份

- 数据库持续归档并支持时间点恢复。
- 事务日志归档复制到中国大陆境内异地在线不可变备份库的周期不超过 15 分钟，用于支撑区域级 RPO 不超过 30 分钟；复制延迟超过 15 分钟时告警并记录暴露窗口。
- 异地离线或气隙副本按介质轮换约定复制，其恢复目标单独定义为 RPO 不超过 24 小时，不用于判定区域级 30 分钟 RPO。
- 附件启用版本、WORM 和异地复制。
- 单独备份配置、证书、模块包、规则包、模型、基础设施定义和密钥恢复材料。
- 每份备份自动校验。
- 定期执行完整隔离恢复并生成审计报告。

## 14. 边缘与断网运行

- 关键工厂和仓库可部署受控边缘节点。
- 边缘节点默认支持 3 天独立运行，并可按容量、安全策略和业务连续性要求延长。
- 离线可正式处理库存、生产、质检和现场工单。
- 使用预分配编号、不可变事件和本地加密存储。
- 财务过账、付款和合同生效必须由中心确认。
- 恢复网络后通过领域事件同步。
- 草稿可字段合并，附件保留全部版本。
- 无法安全合并的数据进入冲突隔离队列。
- 工业网关支持 MQTT、OPC UA、Modbus、PLC，以及现有 MES/SCADA/IoT 平台。
- 核心 ERP 不直接连接设备网络。

## 15. 异常处理与可观测性

### 15.1 错误分类

- 输入校验错误：定位字段并阻止提交。
- 业务冲突：展示冲突对象、版本和处理方式。
- 权限或策略拒绝：提供可理解原因但不泄露无权数据。
- 外部系统故障：进入重试、死信或人工处理。
- 基础设施故障：自动切换、重连或降级。

每个错误包含关联编号、发生时间、可否重试和处理建议。用户界面不展示堆栈、密钥或内部拓扑。

### 15.2 可靠任务

- 命令、支付、同步和 Webhook 必须幂等。
- 数据库事务同时写业务状态和 Outbox。
- 长流程使用持久化 Saga、补偿和人工任务。
- 外部调用使用超时、退避、熔断、死信、重放和对账。
- 财务不平、库存不守恒或金额不一致时禁止静默忽略。

### 15.3 运维中心

- 指标、日志、链路追踪、告警、容量和依赖健康。
- 业务流程、SLA、队列积压、同步状态和用户体验监控。
- 安全与业务风险评分、告警和响应流程可由受控规则配置。
- 内置运维中心。
- 可连接 Prometheus、Grafana、OpenTelemetry 和 SIEM 等外部平台。
- 客户可选择启用仅包含版本、许可证和健康状态的厂商管理通道。

## 16. 性能与容量

首版认证基线（度量对象清单、统计口径、基准数据集规模、测试拓扑和负载模型见附录 A）：

- 100 名内部并发用户。
- 500 名门户并发用户。
- 每秒 1,000 条设备事件，持续 1 小时且测试结束后 5 分钟内积压清零。
- 常规交互 P95 在 2 秒内。
- 普通交易提交 P95 在 3 秒内。
- 常用报表 P95 在 10 秒内。

扩展策略：

- 核心服务水平扩容。
- PostgreSQL Outbox 作为交易可靠性基线。
- 小规模使用轻量队列，规模增长后切换 NATS/Kafka 等外部事件平台。
- 小规模使用内置 Rust 搜索，规模增长后切换独立搜索集群。
- 向量、图和时序同样使用分级后端。
- 分析负载进入独立仓库和语义指标层。
- 优化计算使用确定性约束求解器，AI 负责辅助解释；允许连接外部求解平台。

## 17. 测试与发布门禁

- 多副本定时器：在第 13.1 章的 2 至 3 个核心副本上运行定时器与 SLA 用例，并注入副本重启和网络分区，触发次数必须唯一且不得漏触发。
- 补偿正确性：构造补偿部分失败场景，验证逆序补偿、幂等重试和人工任务兜底，补偿完成后第 17.3 章的会计借贷平衡与库存数量守恒仍成立。
- 流程定义升级：运行中的实例在定义升级和回退后按发起时的版本继续执行至结束。
- 长流程规模：在第 16 章容量基线下与性能与容量测试同批运行，实例查询按第 16 章常规交互 P95 在 2 秒内判定；崩溃后实例恢复按第 13.3 章 RTO 小于 5 分钟判定；归档随容量测试记录耗时，其目标窗口在容量测试方案中单独定义，不套用交互响应目标。
- 外部流程编排平台在启用时执行同一套认证。
- 全部项目通过后，内置流程引擎方可作为跨域一致性的默认实现；未通过时执行第 9.1 章的不达标预案。

### 17.3 强制不变量

- 会计借贷平衡。
- 库存数量守恒。
- 合同、订单、发票、收付款可对账。
- 已过账凭证不可覆盖。
- 权限不能跨法人、字段或密级越权。

### 17.4 供应链安全

- 提供 SBOM 与构建来源证明。
- 支持可复现构建、离线依赖仓库和客户侧验签。
- 严重漏洞 24 小时内提供缓解措施，72 小时内提供正式补丁。上述时效指厂商提供经签名的缓解措施与补丁并通知客户的时间，不包含客户完成安装；移动端具备企业签名/MDM 通道的应用以该通道的可交付时间计时，仅走应用商店分发的应用以第 3.6 章规定的服务端或 Web 侧缓解措施可交付时间计时，应用商店审核周期与客户侧安装窗口均不计入。分发方式、客户侧安装时限、延期规则与台账要求见第 21.13 章。

### 17.5 认证与合规

## 20. 明确排除项

正式版不包含：

- 多语言、多币种、外汇和进出口业务。
- VBA、任意宏和第三方 Excel 加载项执行。
- 完整 Word、PDF/OFD 排版软件。
- CAD 建模与完整 CAD 编辑器。
- 底层企业邮件服务器。
- 完整视频会议基础设施。
- 任意拖拽网站生成器。
- 任意 JavaScript、Python、Shell 或生产 SQL。
- 插件直接访问核心数据库或读取明文机密。
- 公有 AI 处理敏感数据。
- 跨客户模型训练。
- 共享 SaaS 交易数据库。
- 双区域同步 RPO 约为零。
- 四平台像素级一致。
- 所有 OS、云、数据库、存储组合的无限认证。
- 首版预置行业模板。

“所有模块可内置或外接”不等于复制市场上每一家专业软件的全部特性。每个原生模块提供本规格冻结的通用能力基线；更深行业差异通过后续签名行业包或外部专业系统实现。

## 21. 主要风险与控制

### 21.1 范围导致永久不发布

风险：全部模块完成后才 GA，且没有固定期限。

控制：冻结本规格模块目录；内部阶段必须有安装、回退和验收门槛；新增行业需求进入后续行业包。上述控制只约束新增范围，已冻结范围的可交付性另设复核机制：每个内部阶段启动时登记预计工期与最长评估周期，阶段进行中每 3 个月复核一次剩余工作量、退出条件收敛趋势和外部依赖状态；同一阶段连续两次复核未见退出条件收敛，或阶段实际耗时超过登记的最长评估周期时，由产品负责人在降低该模块的通用能力基线深度、将该模块改为只提供外部主系统替换契约、或将该模块推迟到后续签名行业包三条路径中作出范围决策。范围降级决策必须同步修订第 5 章模块目录与第 22 章验收标准并保留决策记录；在规格完成修订前，第 2.2 章的发布约束继续有效，不得以未记录的方式削减交付范围。

### 21.2 多数据库验证矩阵

风险：不同数据库在隔离、锁、迁移、JSON、索引和 HA 上存在差异。

控制：PostgreSQL 参考实现；公共能力基线；固定认证版本；统一事务与业务不变量套件；数据库专用优化。

### 21.3 Tauri 四端成熟度

风险：移动生命周期、外设、无障碍或离线加密未达到要求。

控制：第一阶段真机 PoC；明确门槛；失败时只切换 Flutter UI。

### 21.4 纯 AI 研发的领域责任

风险：财务、税务、薪酬、密码、安全和制造规则出现专业错误。

控制：Codex 承担执行；产品负责人批准；会计、税务、安全、法务、制造等专家在高风险门槛签字验收。

### 21.5 边缘同步冲突

风险：长时间断网产生无法安全合并的库存与生产数据。

控制：不可变领域事件、预分配编号、权威所有者、限时租约、冲突队列；财务、付款和合同保持中心确认。

### 21.6 高可用目标流于配置

风险：架构图满足目标但真实切换、恢复和网络分区失败。

控制：将故障演练、RTO/RPO、完整恢复和容量结果作为发布门禁。

### 21.7 扩展平台成为越权入口

风险：插件、MCP、低代码、SQL 或外部连接器绕过核心权限。

控制：默认拒绝、签名、能力清单、服务端 WASM 组件沙箱、隔离容器、桌面端签名原生插件的子进程隔离、统一安全上下文、无直接数据库访问和不可篡改审计。

### 21.8 白标维护爆炸

风险：每客户独立品牌、证书和商店版本产生持续维护矩阵。

控制：单一核心、配置化品牌、自动化构建/签名/灰度、无客户长期分支；商店政策合规门禁、分发路径选择与签名密钥归属规则见第 3.6 章。

### 21.9 自研持久化流程引擎

风险：内置 Rust 流程与 Saga 引擎承载全部跨域一致性和低代码流程，其幂等、定时器、崩溃恢复与补偿语义出现缺陷时，影响面覆盖所有业务模块。

控制：按第 17.2 章的引擎认证套件独立验证核心语义；阶段 2 退出条件包含该验证；未通过时执行第 9.1 章的不达标预案，改用外部流程编排平台并按第 2.3 章的商业组件采用条件评估。

### 21.10 AI 不确定性

风险：OCR、抽取或模型建议造成金额、账户、税务和合同错误。

控制：字段级置信度、结构化输出、确定性重算、风险分级、人工确认和降级路径。

### 21.11 隐私删除与法律保全冲突

风险：数据主体删除请求与财务、合同、诉讼或 WORM 保留义务冲突。

控制：按适用法律和数据类别执行保留优先级；最小化保留；支持密钥销毁、法律保全、可验证删除和审计证明。

### 21.12 外部准入与真实环境依赖

风险：银行、税务与数电发票、支付、电子签章 CA、应用商店和认证机构的准入周期与结果不受本项目控制。真实环境对接集中在阶段 6 时，模拟器与真实系统的行为差异会在最后阶段才暴露，且任一准入被拒或排期延后都会直接阻塞阶段 6 退出条件与第 22 章验收标准。

控制：准入申请、资质材料准备和机构排期在相关模块进入研发时即启动，不等待阶段 6；研发进度继续以契约模拟器和契约测试解耦，规模化真实环境使用与相应成本仍按第 2.3 章集中在最终验收期。银企直连、数电发票、支付渠道、电子签章和首个白标商店上架为高风险准入项，各自在所属研发阶段的退出条件达成后 1 个月内启动首次真实环境试点，并将试点结果与模拟器契约的差异作为该模块的返工输入。每个外部依赖登记责任人、申请状态、预计周期、最晚启动时间和替代路径，纳入阶段退出条件复核。准入失败或延期时执行替代路径：银企直连改为银行回单与对账文件导入，商店分发按第 3.6 章的被拒与延期处理规则执行替代形态，仅面向内部人员的应用回退到企业签名/MDM 私有分发，面向外部人员的应用回退到外部门户的 Web 与 PWA 形态或改由客户其他已过审商店主体提交，认证机构排期不足时先完成自评估与证据包，正式证明仍按第 17.5 章由具备相应资质的机构实施。替代路径的适用范围、能力差异和退出条件写入交付说明与客户合同。

### 21.13 私有化部署群的补丁分发与漏洞响应

风险：客户实例分散在客户内网、私有云和公有云 VPC，许可证离线验证使部分实例可能长期离线，第 17.4 章的 24 小时缓解与 72 小时补丁承诺不能自动转化为客户侧的实际修复；同时第 9.2 章与第 18 章的升级验证门禁可能阻塞紧急安全补丁，未修复实例持续累积。

控制：责任边界以第 17.4 章为准，24 小时与 72 小时是厂商提供经签名的缓解措施与正式补丁并通知客户的时限，不包含客户完成安装；移动端的计时基准按分发路径区分：具备企业签名/MDM 通道的应用按该通道的可交付时间计时；仅走应用商店分发的外部人员应用按第 3.6 章规定的服务端或 Web 侧缓解措施可交付时间计时。应用商店审核周期不计入，商店受阻时按第 3.6 章的替代形态规则交付。客户侧安装时限在本章唯一定义，其他章节只作指向：严重漏洞补丁自厂商完成签名补丁交付并通知客户之日起 7 个自然日内完成客户侧安装，起算点以交付签收记录的时间为准；分级技术支持套餐可以约定更短时限，不得约定更长时限。客户可在时限届满前提交延期申请，经审批后记录风险接受与新的完成日期，延期期间该实例在台账中保持未修复状态。补丁同时提供受控更新网关在线获取与离线补丁包两种分发方式，离线包附签名、SBOM、哈希清单和回退包，完全离线客户按约定介质渠道交付，交付与安装均产生签收记录。紧急安全补丁仍必须通过第 9.2 章的兼容验证，为满足时限，验证范围缩减为预先维护的、与受影响组件相关的用例集合；验证失败时不放行生产升级，改为下发缓解配置，如关闭受影响功能开关或收紧网关规则，并在客户环境记录暴露状态。厂商依据第 3.3 章的可关闭部署管理通道维护客户实例的版本与补丁状态台账，未启用该通道的客户按支持套餐定期回报；对超过上述 7 个自然日安装时限、或超过已批准延期完成日期仍未安装严重漏洞补丁的实例发出风险告警并留存告知证据。

## 22. 完整正式版验收标准

正式版只有同时满足以下条件才算完成：

1. 冻结模块全部可安装、升级、停用和恢复。
2. 每个冻结模块按附录 B 完成替换能力验收：A 组模块逐一通过外部主系统替换契约测试，其中银行、税务和电子签章完成真实对接验证或附录 B.1 的等效验证；B 组模块按附录 B.1 的能力契约分类清单抽样通过，每个能力契约类至少一个模块通过；C 组模块列入豁免清单并只验收原生能力。机构准入本身不作为发布门禁，见附录 D.5。
3. 黄金业务闭环完整通过。
4. 财务平衡、库存守恒、金额对账和审计验证全部自动化。

### A.3 基准数据集规模

- 设备事件历史 10 亿条。

### A.4 测试拓扑与负载模型

- 测试拓扑与第 13.1 章正式拓扑一致：单区域三故障域、三节点数据库 HA 集群、2 至 3 个核心副本。
- 内部用户负载：100 并发，思考时间 5 至 15 秒，读写比例 7:3，其中提交类操作占 15%。
- 门户用户负载：500 并发，思考时间 10 至 30 秒，以查询与下单为主。
- 设备事件负载：1,000 条每秒持续 1 小时，测试结束后 5 分钟内积压清零。
- 报表负载与交互负载同时施加，不单独测试。
- 每种核心交易数据库分别执行一次完整基线测试。
- 本节负载模型的连续注入时长口径只适用于单次完整基线测试，单次运行时长按 A.2 执行；附录 A.5 的 30 天观测期使用 A.5 单独定义的观测期负载 profile，不按本节的连续注入时长执行。

### A.5 可用性 SLI 与判定方式

- SLI 定义：核心交易 API 在 1 分钟粒度内的成功请求比例，探测点位于负载均衡入口，健康探测频率为每 10 秒一次。
- 不可用判定：1 分钟窗口内核心交易 API 错误率超过 5%，或健康探测连续 3 次失败，该分钟计为不可用。
- AI、OCR、搜索和分析的降级不计入不可用，其可用性单独记录。
- 计划内维护窗口经客户书面确认后豁免，单月豁免时间不超过 21 分钟，即不超过 99.95% 对应的月度错误预算。月度报告必须同时披露含计划内维护窗口的原始可用性数值。计划内维护豁免时间与非计划不可用时间之和不得超过当月错误预算，超出部分计入 SLO 判定。
- 观测期负载 profile：30 天稳态观测期内按工作日每天 8 小时施加 A.4 的内部用户负载与门户用户负载，设备事件按 200 条每秒常态注入，并每日执行一次 1,000 条每秒持续 1 小时的峰值段。A.2 的单次运行不少于 30 分钟只适用于 A.4 的单次基线测试，不适用于本观测期。观测期内新增数据不计入 A.3 冻结基准数据集，观测期结束后回滚到基准快照再执行 A.4 基线测试。
- 发布前判定：预生产环境按上一条的 profile 连续 30 天稳态观测，累计不可用时间不超过 21 分钟，对应可用性不低于 99.95%。稳态观测期不适用计划内维护窗口豁免，非演练停机一律计入累计不可用时间。
- 演练与可用性统计解耦：A.6 全部演练在稳态观测期之外的独立演练窗口执行，演练窗口内的计划停机不计入 30 天累计不可用时间，演练本身按 A.6 判定表逐项单独达标。演练窗口的起止时间必须提前书面报备，实际停机时长与逐项判定结果记入发布证据包；演练窗口内发生的非演练故障计入该次演练的判定，不计入 30 天累计不可用时间。发布门禁要求 30 天稳态观测达标与 A.6 全部演练达标两项同时成立，不得以任一项替代另一项。
- 运行期判定：按自然月度量并出具报告，99.95% 为运行期 SLO，不在发布门禁中重复判定。

### A.6 容灾演练判定表

| 演练场景 | 触发方式 | 判定标准 |
|---|---|---|
| 单核心副本失效 | 强制终止进程 | 无失败事务，恢复时间小于 1 分钟 |
| 单故障域整体失效 | 断开该故障域网络 | 已向客户端返回成功的事务零丢失，RTO 小于 5 分钟 |
| 数据库主节点失效 | 强制终止主节点 | 已提交事务零丢失，自动切换完成时间小于 5 分钟 |
| 网络分区 | 隔离一个故障域 | 不出现双主，不产生数据分叉 |
| 区域灾难 | 停止全部三个故障域并从异地不可变备份恢复 | RTO 不超过 8 小时，RPO 不超过 30 分钟 |
| 完整恢复演练 | 从备份重建全部数据、配置与密钥材料 | 恢复后通过第 17.3 章全部强制不变量校验 |

每类演练在发布前至少执行两次，两次均达标才判定通过。全部演练在 A.5 定义的独立演练窗口内执行，演练停机不计入 A.5 的 30 天稳态观测统计。区域灾难演练从中国大陆境内异地在线不可变备份库恢复，RPO 判定以第 13.4 章约定的事务日志归档复制周期不超过 15 分钟为前提；从异地离线或气隙副本恢复时按第 13.4 章的离线层级目标单独判定，不用于判定区域级 30 分钟 RPO。

- 每个能力契约具有唯一编号与版本，模拟器按契约实现，不得为通过测试放宽校验。
- 模拟器必须覆盖成功、业务拒绝、超时、重复投递和字段所有权冲突五类用例。
- 真实外部系统结果与模拟器结果不一致时，以真实系统为准并修订契约与模拟器。

### B.4 豁免清单口径

- 豁免由产品负责人批准，逐模块记录理由、影响范围和复评时间。
- 豁免清单随每次发布进入验收证据包，并在管理员文档中说明该模块首版不支持外部主系统替换。
- 未记入豁免清单的模块一律按 B.1 分组执行验收，不得默认通过。

## 附录 C 四端客户端 PoC 量化门槛

本附录是第 6.1 章真机 PoC 的判定依据，也是第 19 章阶段 1 退出条件的判定依据。C.2 的移动端通过线在阶段 1 判定后继续作为正式版移动端验收通过线：其中移动端时延通过线由第 22 章第 7 条引用并判定，其余门槛项按第 22 章第 5 条与第 6.2 章的等价定义与豁免清单判定。门槛表在阶段 1 启动前冻结。

### C.1 测试设备基线

- Windows：近五年主流商用笔记本，8 核、16 GB 内存。
- macOS：Apple Silicon 入门机型，16 GB 内存。
- iOS：仍在厂商安全维护期内的最低配在售机型，以及一台上市约四年的旧机型。
- Android：一台主流旗舰机、一台中端机、一台工业 PDA。
- 每项指标以旧机型或中端机的结果为准。

### C.2 门槛项

| 验证项 | 通过线 |
|---|---|
| 冷启动 | 桌面端 3 秒内、移动端 2.5 秒内进入可操作界面 |
| 列表滚动 | 1 万行虚拟列表滚动平均帧率不低于 55 fps，掉帧比例不超过 1% |
| 交互时延 | 附录 A.1 常规交互清单的移动端等价场景 P95 不超过 2.5 秒；该值为移动端专用通过线，不替代附录 A.2 的桌面端通过线 |
| 内存占用 | 移动端常驻内存不超过 500 MB，连续操作 2 小时无持续增长 |
| 中文输入 | 系统输入法在表单、表格和搜索框中无丢字、无候选错位，可调用手写与语音输入 |
| 无障碍 | WCAG AA 自动检查零严重问题，四端各完成一次读屏软件端到端下单流程 |
| 相机与扫码 | 连续扫码 100 次识别率不低于 99%，单次识别不超过 1 秒 |
| 推送 | 前台、后台和被系统回收三种状态下到达率不低于 99%，端到端时延 P95 不超过 10 秒 |
| 离线加密 | 本地加密数据库随机读写吞吐不低于 20 MB/s，10 万行离线数据集查询 P95 不超过 1 秒 |
| 生物识别 | 四端均可调用系统生物识别并返回可验证结果，失败可回退到强口令与设备证书 |
| MDM | 至少两款主流 MDM 产品完成注册、策略下发、远程擦除和合规检查 |
| 工业外设 | 桌面端完成扫描仪、标签打印机和 USB Key 各一次端到端验证；移动端完成蓝牙标签打印与 RFID/NFC 读写各一次 |

### C.3 判定规则

- 全部门槛项通过，或未通过项已获书面批准豁免时，客户端路线判定为 Tauri。
- 出现下列任一情形时，UI 层切换为 Flutter，Rust 核心保持不变：任一移动平台的冷启动、列表滚动或交互时延门槛未通过且无可行优化路径；无障碍或中文输入门槛在移动端未通过。
- 推送与离线加密门槛由 Rust 核心、推送网关和设备密钥硬件承担，不属于 UI 层可归因项；未通过时按 Rust 核心与推送网关的专项优化任务处理，列入阶段 1 遗留项，不触发 UI 技术栈切换。
- 桌面端工业外设与 MDM 门槛未通过时，优先通过第 9.3 章的桌面端签名原生插件补齐，不触发 UI 技术栈切换。
- 移动端不适用签名原生插件补救路径。移动端的蓝牙、NFC 与相机类门槛未通过时，只能通过应用版本内静态签入的能力集修复；其余外设按第 6.2 章豁免清单的代理执行路径验证。
- 判定人为产品负责人；判定结论与全部原始测量数据纳入阶段 1 验收证据包。

## 附录 D 认证矩阵清单

### D.1 组合原则

- 采用基线组合加单维度替换的方式：冻结 4 个完整基线组合，其他取值在指定基线组合上做单维度替换验证，不做全量笛卡尔组合。
- 每个维度只认证公开声明的认证版本；版本升级按第 18 章流程重新验证。
- 单维度替换验证的通过标准与基线组合一致。
