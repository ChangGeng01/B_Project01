## 3. U-A：全局取值

### U-A-07 受控取值清单与维护方式

除科目类别外，十一类业务字典均允许经签名配置包新增、修改显示名、调整排序与停用。编码一经被业务记录引用，不得修改或物理删除，只能停用；停用值在历史记录中继续正常显示。

| 字典 | 出厂编码 |
|---|---|
| 客户类型 | `ORGANIZATION`、`INDIVIDUAL`、`OVERSEAS` |
| 供应商分类 | `MATERIAL`、`SERVICE`、`MIXED` |
| 物料类别 | `RAW_MATERIAL`、`FINISHED_GOOD`、`CONSUMABLE`、`SPARE_PART` |
| 产品类别 | `GOODS`、`SERVICE`、`SUBSCRIPTION`、`RENTAL` |
| 退货原因 | `QUALITY_ISSUE`、`WRONG_ITEM`、`DELIVERY_DAMAGE`、`CANCELLED`、`OTHER` |
| 订单关闭原因 | `FULFILLED`、`CUSTOMER_CANCELLED`、`SUPPLIER_CANCELLED`、`CONTRACT_TERMINATED`、`OTHER` |
| 风险类型 | `QUALITY`、`DELIVERY`、`PRICE`、`COMPLIANCE`、`FINANCIAL`、`OTHER` |
| 工单类型 | `INSTALL`、`REPAIR`、`CONSULT`、`COMPLAINT_FOLLOWUP` |
| 投诉渠道 | `PHONE`、`EMAIL`、`ONSITE`、`SALES_RELAY` |
| 设备状态 | `IN_STOCK`、`IN_SERVICE`、`UNDER_REPAIR`、`SCRAPPED`、`RETURNED`；每个新增状态必须声明 `is_terminal` |
| 工单优先级 | `LOW`、`NORMAL`、`HIGH`、`URGENT` |
| 科目类别 | 固定为 `ASSET`、`LIABILITY`、`EQUITY`、`PROFIT_LOSS`；只允许本地化显示名，不允许新增编码 |

### U-A-08 默认审批链

主数据出厂五条单节点链：

- 客户：`MDM_CUSTOMER_APPROVER`
- 供应商：`MDM_SUPPLIER_APPROVER`
- 物料：`MDM_MATERIAL_APPROVER`
- 产品：`MDM_PRODUCT_APPROVER`
- 仓库：`MDM_WAREHOUSE_APPROVER`

每类档案的新建、变更、停用与启用复用该对象所属链。其余出厂链固定如下：

| 场景 | 默认审批角色 |
|---|---|
| 采购订单、采购退货 | `PROCURE_MANAGER` |
| 销售退货 | `SALES_MANAGER` |
| 信用超额 | `FINANCE_MANAGER` |
| 发票作废与红字冲销 | `FINANCE_MANAGER` |
| 付款、客户退款、供应商返款 | `FINANCE_MANAGER` |
| 资金账户维护 | `FINANCE_MANAGER` |
| 期间关账、年度结转 | `FINANCE_MANAGER` |
| 期初余额、受控更正凭证 | `FINANCE_MANAGER` |
| 配置发布 | `SECURITY_ADMIN` |
| 企业报表发布 | `MANAGEMENT_APPROVER` |

到款登记出厂不审批，`EP__FINANCE__RECEIPT__REQUIRES_APPROVAL=false`。合同审批与发票申请中的管理者必经节点按 U-B-03。上述默认链允许客户经签名配置发布通道替换，但不得取消自审禁止、顺序执行与节点展开为空时拒绝提交三项控制。

### U-A-09 批量导入

全部 Excel/CSV 导入采用两遍处理：

1. 第一遍完整解析文件，校验模板版本、列集合、类型、必填、文件内重复、行数上限及能够脱离数据库完成的跨行约束；任一错误则整份文件零写入。
2. 第一遍通过后逐行使用独立事务执行动态业务校验与幂等写入；并发变化或动态冲突只使该行失败，已经成功的行不回滚。

上限固定为：账号 200 行、主数据 5000 行、发票 2000 行、财务期初 2000 行。结果必须返回成功数、失败数、成功对象编号，并生成包含行号、字段、错误码、说明与建议动作的错误文件。总账期初允许逐行进入同一草稿批次，但借贷不平的批次不得确认。

### U-A-12 银行字段

`bank_name` 与 `bank_account_no` 均登记为密级 30 并加密存储。列表中账号固定 `KEEP_LAST_4`，银行名只对具备财务字段读取权限的主体显示；详情默认仍只显示账号末四位，完整查看必须走专用能力、重新认证并写审计。标准导出不输出完整账号；任何包含银行名或账号的导出均按敏感导出处理，必须重新认证和审批。

## 4. U-B：角色与授权

### U-B-01 标准角色包

首版随产品交付五个可复制派生的标准业务角色包：

| 角色包 | RoleCode |
|---|---|
| 销售 | `SALES_USER`、`SALES_MANAGER`、`MDM_CUSTOMER_APPROVER` |
| 采购 | `PROCURE_USER`、`PROCURE_MANAGER`、`WAREHOUSE_USER`、`SUPPLIER_ADMIN`、`MDM_SUPPLIER_APPROVER` |
| 财务 | `FINANCE_ACCOUNTANT`、`FINANCE_MANAGER`、`REPORT_DESIGNER` |
| 技术 | `TECHNICIAN`、`PROJECT_MANAGER` |
| 管理与运营 | `MANAGEMENT_APPROVER`、`OPS_DATA_OWNER`、`MDM_MATERIAL_APPROVER`、`MDM_PRODUCT_APPROVER`、`MDM_WAREHOUSE_APPROVER` |

五类管理员职责角色继续独立，不并入业务角色包。RoleCode 不可改，显示名可改；派生角色复制权限后独立版本化。出厂包不自动绑定任何自然人。

### U-B-02 岗位名称归并

实施向导使用 `SALES`、`PROCUREMENT`、`WAREHOUSE`、`FINANCE`、`SERVICE`、`PROJECT`、`MANAGEMENT`、`DATA_OPS` 八个规范岗位标签，把客户现有岗位显式映射到 U-B-01 RoleCode；不得按中文名称自动猜测。任务负责人、记录责任人、申请人和当前处理人是记录关系，不另建角色。配置管理员属于既有管理员职责角色，不与 `REPORT_DESIGNER` 混同。

### U-B-03 管理者必经节点

合同审批与发票申请的出厂必经管理节点固定为单节点 `approver_kind=ROLE`、`role_code=MANAGEMENT_APPROVER`。首版不按金额分档，也不读取部门上级链。客户可在既有审批链模型中替换为 `ROLE`、`POSITION` 或 `DEPT_MANAGER`，但金额条件不进入首版 schema。

### U-B-04 技术角色边界

`TECHNICIAN` 可登记安装、调试、维修和交付证据，可读取不含价格的合同摘要；不得读取合同总额、单价、成本、毛利，不得执行最终交付确认、收入确认或财务审批。最终交付确认由 `SALES_MANAGER` 或 `PROJECT_MANAGER` 执行。

### U-B-07 记录级权限

默认可见来源仅为记录责任人、当前流程处理人和显式共享。创建人不因创建过记录而永久保有权限，除非同时是责任人。共享不可再转授，`can_reshare=false`。三类来源取并集，任一命中后仍须继续通过法人、对象、字段、密级和显式拒绝判定。

### U-B-12 门户账号计数

门户用户计入同一约 50 个启用命名用户池；同一身份跨多个法人或供应商绑定只计一次。每个“供应商 + 法人”最多 3 个启用门户账号，停用账号不计入启用数。

### U-B-15 审批节点上限与超时

审批链最多 10 个节点。节点默认超时 24 小时，之后每 24 小时重复提醒；不自动升级、不自动通过、不自动驳回。转派只能由有权人员人工执行，并完整记录原处理人、新处理人、原因和时间。

### U-B-18 敏感导出

结果包含敏感字段、对象密级不低于 30、或导出行数不少于 1000，任一成立即为敏感导出；审计记录导出始终敏感。敏感导出须重新认证和审批，非敏感导出仍写审计。格式固定为 XLSX、CSV、PDF，单次最多 50,000 行。

## 5. U-C：模块归属与编排

### U-C-02 收货与交付操作者

收货录入和过账仅 `WAREHOUSE_USER`；采购员可准备、查看和补充采购信息，但不能过账。仓管负责出库与发运事实，最终交付确认由 `SALES_MANAGER` 或 `PROJECT_MANAGER` 执行。

### U-C-03 收货岗位归属

仓管员是收货登记的唯一业务操作者。采购员不得以共享记录、创建人或采购订单责任人的身份绕过 `WAREHOUSE_USER` 能力检查。

### U-C-06 仓库档案归属

仓库唯一归 `mdm` 模块，阶段 5 建立 `mdm.warehouses`，并交付仓库建档、变更、停用、启用、第五条主数据审批链及引用探针。阶段 8 不建立第二张仓库表，只实现 `WarehouseDeactivationCheckPort` 的库存侧使用检查，并通过 MDM 提供的仓库查询契约读取。通用地点主数据首版延期，不得为承载仓库而建立一套通用地点表。

### U-C-09 已退货未冲回成本

触发点为直运采购退货上的“供应商拒绝接受退回”动作。`PROCURE_MANAGER` 提交证据与原因，`FINANCE_MANAGER` 重新认证并审批；批准事务调用 `CostReturnMarkPort`。标记不得直接撤销或删除；事实变化时追加引用原记录的成本冲回或更正条目，原标记作为历史证据保留。

### U-C-12 报表配置治理

个人报表定义状态为 `DRAFT / ACTIVE / RETIRED`，只限本人和当前环境，不可共享、调度、作为企业模板或跨环境导出定义，不走签名发布。企业报表定义状态为 `DRAFT / PENDING_APPROVAL / PUBLISHED / DEACTIVATED`，必须走差异审查、审批、签名发布和对象版本回退。提升操作复制个人版本生成新的企业草稿，不原地改变个人对象身份。

## 6. U-D：账务与采购控制

### U-D-01 无物料服务产品

无关联物料的服务产品必须取 `costing_mode=DIRECT_EXPENSE`。交付确认产生收入，但不产生库存腿或虚构的销货成本腿；实际成本只来自关联的直接费用采购发票或成本捕获。实际成本未到时，毛利显示“暂估/成本缺失”，不得用合同估算数生成凭证。

### U-D-17 预付款累计上限

每条预付款必须且只能引用一张采购订单或合同。上限优先取付款计划授权额，无付款计划时取引用单据价税合计。在锁内校验“已支付 + 审批中/已批准未支付 + 本次申请”不超过上限；驳回、撤回或作废释放未支付占用，已支付金额只有正式冲正后才减少。

### U-D-18 采购价格控制

存在生效供应商价格时自动带出并在订单行冻结价格来源快照。允许无价格记录或人工改价，但必须填写原因；无价格记录或高于生效价时置 `price_exception=true`，由采购订单既有的 `PROCURE_MANAGER` 审批节点处理，不建立第二套采购价格审批系统。

## 7. U-E：信用

### U-E-03 信用占用口径

在途订单、已交付未开票与应收未收三桶统一使用价税合计口径。`finance.unbilled_ar_entries` 在 net 外同时保存 gross；交付/开票/冲销/退货同步命令均携两列。现有 `v_unbilled_ar_net` 同时输出 net_balance 供会计勾稽与 gross_balance 供信用；`ReceivableExposureQuery` 字段唯一命名为 `delivered_unbilled_gross_amount`，取 `greatest(gross_balance,0)`。三桶只用 gross，科目/总账勾稽仍只用 net，任何返回净额的旧端口字段均被替代。

### U-E-07 信用超额审批

信用超额出厂为单节点 `FINANCE_MANAGER`，申请人不可自审；不再由 `SALES_MANAGER` 审批。

## 8. U-F：采购自动化与门户

### U-F-02 库存不足采购需求

补货策略挂在“法人 + 仓库 + 物料”，唯一物理存储为 `inventory.replenishment_policies`，字段为 `reorder_point` 与 `target_stock`，满足 `target_stock >= reorder_point >= 0`，首版不另设安全库存字段；两阈值同空表示停用，禁止只填一项。库存阶段拥有策略存储、A11 查询、A12 受授权配置入口与 `ReplenishmentPolicyReadPort`；销售阶段用与 A2 完全相同的 `SalesAwareAvailabilityQuery` 组合实现 `ReplenishmentPolicyQuery`；采购阶段只注入并消费该组合端口，不保存阈值、不重算第二套可用量。`available_qty <= reorder_point` 时触发，建议量为 `max(target_stock - available_qty, 0)`。每 60 分钟扫描一次，部署默认关闭；阈值为空时跳过。开启后同一法人仓库物料组合只保留一张未结自动采购需求，重复扫描不得重复建单。策略配置、销售可用量守卫与采购扫描共享同一组合锁序，开发时不得另行选择所有权或算法。

### U-F-10 门户字段白名单

阶段 7 第 4.7 节白名单获准作为首版基线，发票上传部分必须按 F-50 改为头 + 行：头不含单一税率，行包含税率、净额、税额和价税合计。

- 采购订单只返回本供应商自己的订单编号、日期、状态、行、物料、数量、单位、订单单价/税率、交期与交货批次。
- 送货通知只返回自身通知、订单行引用、数量、批次/序列号、预计到货、承运方和运单号。
- 对账只返回自身订单、收货、已登记进项发票、付款及有效未核销余额。
- 自身档案只开放资质、价格、交期及变更申请状态。

禁止返回客户、销售订单、合同、项目、内部备注/附件、审批痕迹、成本、毛利、其他供应商、银行账号；不提供通用查询和导出入口。每次请求同时断言供应商和法人范围，写操作重读状态并按 `row_version` 拒绝陈旧提交。

### U-F-11 受限自助注册

首版只允许邀请开通，`EP__PORTAL__SELF_REGISTRATION__ENABLED=false`。现有受限注册代码可以保留，但只有许可证、签名配置与安全审批三者同时满足才允许启用；待审核账号只能访问自身注册状态。首版发布不以启用自助注册为验收项。

## 9. U-G：库存

### U-G-01 库存可用量

`available = on_hand - 已确认或已下达且尚未交付的销售订单剩余量`，按法人、仓库、物料计算。首版不建持久化预留表；销售订单确认时对同组合加锁并重算，避免并发超卖。取消、关闭和实际交付应立即减少对应未交付量。

### U-G-07 库存与设备序列号

序列号在法人内全局唯一，`inventory.serial_states` 是库存来源序列号的权威登记。库存来源设备引用该记录，不保存第二份权威序列号。手工设备没有可引用的库存序列号时可留空并使用设备编码；首版不建立第二套设备序列号命名空间。与 U-J-03 使用同一判据。

## 10. U-H：总账

### U-H-16 科目模板与年结绑定

随产品提供可导入但不自动启用的参考科目表，覆盖全部 17 个科目角色，并明确绑定 `PROFIT_THIS_YEAR` 与 `RETAINED_EARNINGS_UNDISTRIBUTED`。每法人由实施人员选择导入，再由 `FINANCE_MANAGER` 审批；具体科目代码和名称在生产启用前须取得专业会计签字。

### U-H-17 补记

记账日期默认取业务单据日期。改为早于登记日时必须具备 `LEDGER_BACKDATE` 权限、重新认证并经 `FINANCE_MANAGER` 审批；只能落在开放期间，关闭期间继续执行既有顺延规则。审计同时记录原日期、登记时间、修改人和审批引用。

### U-H-18 数据责任人

`OPS_DATA_OWNER` 按法人授予，可兼任 `FINANCE_ACCOUNTANT`，不得兼任 `FINANCE_MANAGER`；无论兼任关系如何，均不得审批本人发起的数据修复。

## 11. U-I：报表

### U-I-06 报表缓存

首版不缓存、不物化，每次使用同实例只读角色实时查询。响应和界面均显示精确到秒的 `data_as_of`。

### U-I-11 报表导出

完全复用 U-B-18：XLSX、CSV、PDF，单次最多 50,000 行；按敏感字段、密级 30、1000 行阈值分级，审计导出始终敏感；敏感导出重新认证并审批。

### U-I-12 报表对象状态与回退

完全复用 U-C-12。个人对象只做个人版本；企业对象按发布版本整体回退，不对同一版本内的单个字段做局部回退。

## 12. U-J：售后、设备与项目

### U-J-03 设备序列号唯一性

与 U-G-07 同值：法人内全局唯一，库存来源序列号以 `inventory.serial_states` 为权威，设备台账不得另立同名权威记录。

### U-J-04 工单状态扩展

工单状态固定为 `DRAFT / PENDING_ACCEPTANCE / IN_PROGRESS / PENDING_CUSTOMER_CONFIRM / COMPLETED / CANCELLED`。低代码只能在既有迁移上增加审批、提醒和时限，不能新增状态或迁移。

### U-J-07 工单重开

终态记录不原地重开，原地重开次数为 0。`COMPLETED` 可通过“创建返修跟进”生成新工单并写 `follow_up_of_work_order_id`，跟进次数不设硬上限；`CANCELLED` 只能新建独立工单。原工单和全部处理记录永久保留。

### U-J-08 换货配对

`EXCHANGE` 必须同时关联销售退货行和替换发货行，且客户、产品一致；两侧都到终态后登记行才能完成。只退不换使用 `RETURN`，只补发使用独立补发动作，不得伪装成 `EXCHANGE`。

### U-J-13 合同变更与续签后的任务

终态派生任务永久保留。不再需要的未终态任务不自动删除或取消，置 `derivation_stale=true` 并生成给 `PROJECT_MANAGER` 的处置事项。新增或改变的义务创建补充任务，使用新版本唯一键；旧任务由负责人明确完成或取消。

## 13. U-K：低代码与客户端

### U-K-01 配置发布粒度

配置按整包原子发布和回退，不提供单对象发布。并发编辑锁按内容项，TTL 固定 1800 秒；行级乐观锁继续生效。

### U-K-07 白标范围与默认值

`brand_profiles` 当前完整列集即首版最终范围，包含产品名、厂商显示名、四端标识、Logo、启动图、登录背景、主题色、通知模板、签名引用和发布渠道。开发/测试回退值为产品名 `Enterprise Platform`、厂商 `Local Development`、四端标识以 `local.enterprise.platform.*` 开头，并明确标记不可发布。生产构建必须提供客户正式品牌、包标识、Logo、签名身份和商店主体。

### U-K-09 引导与演示数据

交付本地上手清单。演示数据只允许生成在物理隔离的 `DEMO` 部署或配置档，一键重置只在 DEMO 生效，生产环境硬拒绝；禁止把真实客户数据复制到演示环境。

## 14. U-L：非功能与运行约束

### U-L-01 并发行为

活跃并发定义为最近 60 秒内有请求的不同用户数。超过 20 人不拒绝登录、不拒绝写入，只记录、告警并声明性能 SLA 不再适用。管理端显示当前值并每 5 秒刷新。单用户最多 3 个会话，建立第 4 个时撤销最早会话。

### U-L-05 单文件上限

部署默认 5 GB，允许按模块和文件类型配置更低上限，有效值取所有适用规则的最小值。可调区间为 1 MB 至 5 GB；门户硬上限 50 MB，移动端只能进一步降低。调整须经签名配置发布、`SECURITY_ADMIN` 审批和审计，只影响新上传。

### U-L-07 弱网与重连

最近 5 次请求滚动中位 RTT 大于 2 秒，或 60 秒内发生两次网络失败，判为弱网；操作系统报告离线或连续 3 次网络失败，判为离线。客户端显示持续横幅，修改后 5 秒写入本地加密草稿。重连后读请求可自动刷新，写请求绝不自动重提交，必须由用户逐单确认；服务端幂等键继续兜底。

### U-L-08 浏览器与操作系统支持

Chrome、Edge 支持当前及前两个稳定大版本，Safari 支持当前及前一个大版本，Firefox 支持当前 ESR；只支持仍接受厂商安全更新的操作系统。每次发布以签名兼容清单冻结实际最低版本。不支持或已停止安全更新的版本硬拦截并显示升级说明。

### U-L-09 升级停机窗口

计划维护提前 7 天和 24 小时通知，开始前 15 分钟应用内倒计时。切换开始即拒绝新提交，服务端已经执行的请求最多等待 5 分钟，之后幂等中止。未提交内容先进入本地加密草稿；升级后只自动恢复 schema 兼容草稿，不兼容草稿保留为只读复制/导出，不自动提交。紧急安全升级应尽早通知并记录紧急原因。

### U-L-12 派生数据新鲜度

搜索、报表和其他派生读数均返回 `data_as_of` 或 `indexed_at`，精确到秒。延迟超过 30 秒或无法判断时显示“可能不是最新”，提供刷新与跳转权威记录入口；超过现行 15 分钟传播窗口仍未完成时进入运维告警。核心交易不因派生存储延迟而阻断。

## 15. 本轮一并批准的技术冻结

这些项不是上述 47 行的扩展问题，不再留到落码时重新选择：

1. **BlindIndex 固定 32 字节。** `derive_blind_key`、盲索引列、测试向量与跨法人派生均使用完整 `[u8; 32]`；16 字节截断及“16/32 可配置”全部作废。
2. **Windows 原生部署；Hyper-V 仅有 F-55 插件窄例外。** 首版产品服务端与依赖直接运行在认证过的 Windows Server 主机上，不得把整个平台放入 Hyper-V 客户机，也不得借虚拟机恢复已删除的 Linux/cgroup 或资源隔离语义。后续最高裁定 F-55 §4.5 仅允许 `LOCAL_WINDOWS_HYPERV_CONTAINER` 为单次受控 MCP 插件调用建立短命 Hyper-V-isolated utility VM；它不承载产品服务、数据库或客户主数据卷，不能类推为第二套部署形态。
3. **阶段 13a 执行薄 PoC。** 在 iOS 与 Android 真机按规格切栈触发项进行早期验证；薄 PoC 可以作出“切离 Tauri”的否定结论，但不能单独证明 Tauri 全表通过。完整无障碍与全能力矩阵仍由阶段 13 后续全表验收承担。
4. **生产制品使用 Authenticode。** Windows 生产 EXE、DLL、MSI 与升级包必须由客户或交付主体认可的 Authenticode 身份签名并在安装/升级前验证；内部 ECDSA 配置/许可证签名不能替代它。
5. **CI 唯一入口为 `cargo xtask ci`。** 内网平台固定 Forgejo + Woodpecker，Windows 构建 agent 执行该入口；不得让 `.github` 脚本成为第二套权威流水线。
6. **GRNI 使用 procure 追加效果回写。** `procure` 建立仅追加 GRNI 效果事实，金额使用正数加 `INCREASE/DECREASE` 方向；收货、采购退货、进项发票受理和进项红字按实际会计期间追加效果。阶段 10 经 `ep_contract_procure::GrniEffectWritebackPort` 在同一事务回写，`GrniSubledgerBalanceQuery` 只读 procure 自有表并按截至期间累计，不跨读 invoice schema、不以当前 `invoiced_quantity` 倒推历史。
7. **内部对账系统上下文。** `SecurityContext` 固定新增第 20 字段 `system_purpose: Option<SystemPurpose>`，枚举固定为 `SystemPurpose { General, Reconciliation }`。系统构造器签名为 `SecurityContext::system(legal_entity_id, request_id, trace_id, purpose)`，其中 `purpose` 写入 `Some(purpose)`；人工上下文固定为 `None`。不新增 `ReconContext`，不增加 `with_*` 权限变换方法。`SystemPurpose::Reconciliation` 除定义处外只允许在 `crates/platform/recon/src/executor.rs` 构造，由 `reconciliation-context-confined` archcheck 断言；job-worker 只调用 `ReconExecutor::run`，不得自行构造对账上下文。对象越权统一返回 `PLATFORM.AUTHZ.OBJECT_FORBIDDEN`。戊-11 据此关闭。
8. **F-50 范围保持完整。** F-50 的 **45** 项验收、32 条错误码（F-50 设计 §11 实数 45 条、序号 1–45 连续；本行原写 44，与 00c 同批更正，F-62；按本文 §1 冲突规则本行为权威，故此处必改）、行级发票、中央号码登记、显式核销效果、`effective_open`、历史追加切片、门户头行上传与受理回写均在首版范围内；F-51 不得用“低成本”理由删减其中任何一项。
