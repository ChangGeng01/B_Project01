- 入站 JSON-RPC error `data` 只有两种 strict 形状且字段顺序固定：普通 `{stable_code,request_id}`；唯一 version 特例 `{stable_code:"MCP.PROTOCOL.VERSION_UNSUPPORTED",request_id,supported:["2026-07-28"],requested}`。特例仅在 header/body requested version 逐字相等且是 1..64 visible-ASCII、但非支持值时返回 HTTP 400/`-32022`；缺失、超限、非可见 ASCII或 header/body 不等均为 HEADER_MISMATCH 且不回显。error envelope 总含 `id`，不可确定时为 null，不附 details/name/URI/policy facts；不要求第三方远端原样生成此 data。
- 请求 1,048,576 bytes、响应 8,388,608 bytes、调用 30,000 ms、connector inflight 4、每分钟 60 次；远端 connect 5,000 ms，本地启动 10,000 ms。
- `/mcp` 是普通同步 HTTP 8 秒/20-slot 交易闸门的唯一 MCP 具名例外：基础 transport/body/token identity 校验后先生成 invocation/event ids，并在 caller completion spool 物理预留且 flush 完成 slot，再进入独立 connector-keyed 公平全局 16-slot semaphore，最后取该 connector 固定 4-slot；slot 预留失败必须保持零 permit、零 rate、零 counter、零 ATTEMPT、零 dispatch。两层 semaphore 不占普通 20-slot、不可借位/配置放大，无位返回 `MCP.RATE_LIMITED` 且不消费 proof counter。取得两 permit 后才原子消费 proof；专用 Tower timeout 32000 ms，内部 30000 ms 从 proof 受理起覆盖 binding/dispatch/response，余 2000 ms 只供取消、completion/spool 和错误封套，普通 8 秒 layer 不得提前截断。
- 入站 grant issue 的 `ttl_seconds,max_calls` 都可选：省略时分别取当前 `mcp.grant_ttl_seconds` 与 `mcp.max_calls_per_grant`；显式值分别必须在 `1..=当前配置`，0 或超限以 `PLATFORM.REQUEST.INVALID_PAYLOAD` 拒绝。两配置默认 600/100，验证范围与硬上限分别 `1..=600`/`1..=100`。token 唯一 wire grammar 是 50 个 ASCII bytes：`epmcp1.` + 对恰好 32 个 CSPRNG bytes 做 RFC 4648 §5 base64url-no-pad 的 43 字符，正则精确为 `\Aepmcp1\.[A-Za-z0-9_-]{43}\z`；canonical parse 必须 decode 成 32 bytes 且 no-pad re-encode 与完整输入逐 byte 相等。`token_hash` 与 DPoP 中 bearer digest 都取完整 50-byte ASCII token 的 SHA-256，禁止只 hash 随机段或 decoded bytes；数据库只存该 hash。每次请求还必须用来源设备 ECDSA P-256 私钥给出逐次 PoP，counter 必须等于持久 `last_proof_counter+1`、timestamp 在服务端时间 ±60 秒内；登出或绑定事实失效立即失效。
- counter UPDATE 成功后的即时 JSON、SSE 初始 HTTP response 及后续业务/授权/外部错误必须带唯一产品 header `X-EP-MCP-Proof-Counter-Accepted: <counter>`；UPDATE 前拒绝绝不带。代理仅透传、不记录/通配暴露；客户端只有收到 exact 值才前进本地 counter，网络不确定时撤销并重签。

- LOCAL 安装收据字段不形成发布循环：十五列 materialization group 恰为 `install_receipt_id,installed_root_ref,installed_at,hcs_image_identity,installed_root_sd_sha256,sandbox_profile_name,sandbox_sid,wfp_provider_guid,wfp_sublayer_guid,wfp_connect_v4_filter_key,wfp_connect_v6_filter_key,wfp_recv_accept_v4_filter_key,wfp_recv_accept_v6_filter_key,wfp_resource_assignment_v4_filter_key,wfp_resource_assignment_v6_filter_key`。DRAFT/PENDING_APPROVAL/APPROVED 可保持整组 joint NULL；仅 APPROVED 行可执行一次 all-null→complete 原子补全。两种 local 都写 receipt/root/time/root-SD，stdio 另写十个 sandbox 值且 HCS identity 为空，Hyper-V container 写 HCS identity且十个 sandbox 值为空；ACTIVE 前必须完整，补全后及所有终态均不可变。rollback 新 DRAFT 复制已验真的内容/附件 identity，但绝不复制旧安装收据或 materialization 字段。
- stdio 物化根必须是 manifest-version-specific `C:\ProgramData\EnterprisePlatform\mcp\packages\<manifest-version-uuid>\<package-digest>\` 与同形 `ep-install://mcp-stdio/<manifest-version-uuid>/sha256/<digest>`；同 CAB 跨 connector/版本/回退也必须完整复制到新根，禁 hardlink/reflink/block-clone/共享文件对象。每个 version root 只授其唯一 exact AppContainer SID。Hyper-V image root 可按 digest 共享，但 HCS image 只有在扫描全部 connector/manifest 后证明相同 image identity 零引用才能 GC。

- plugin-host、stdio child 与 Hyper-V guest 在启动前必须 readback 证明 WER 上传与 full/user dump 均禁止，无可承载 payload/secret 的 LocalDumps 目的地；不可判定则对应 transport 不启用。crash canary 在 stdin/secret pipe 注入标记后强制异常，必须证明 dump/WER/Event Log/最小故障证据中零标记/业务 bytes；故障证据只含 invocation/build/package digest、exit/exception code 与时间。

- `McpLocalArtifactManifestV1.artifact_kind` 的 wire 闭集恰为 `MCP_SIGNED_STDIO_PACKAGE|MCP_WINDOWS_HYPERV_CONTAINER`，分别且只能对应 `LOCAL_SIGNED_STDIO|LOCAL_WINDOWS_HYPERV_CONTAINER`，并与外层 `SignedArtifactKindV1`/receipt kind 逐字相等；Rust variant 名、简称、别名均拒绝。`artifact_code` 匹配 `[a-z][a-z0-9._-]{0,63}`，`artifact_version` 匹配 `[A-Za-z0-9][A-Za-z0-9._+-]{0,63}`；二者只是签名包运维显示身份，不参与 connector 路由、权限、版本选择或兼容判定，同一验签 CAB 仍须按每 connector/version 的独立物化规则复制。

- `receipt_id` 跨 `platform_ops.ai_model_packages` 与 `platform_meta.mcp_manifest_versions` 全局唯一：共享 core handler 的事务第一步固定执行 `pg_advisory_xact_lock(hashtextextended(lower(receipt_id::text),4995704681966667073))`，随后交叉查两表；lost-ACK replay 从目标行重建并比较除 transport correlation `request_id` 外全部持久语义，即 schema version、artifact kind、package/manifest digest、root ref、installed-at 与完整 subject。首次/replay ACK 都回显当前请求 id，字段恰为 `request_id,receipt_id,registered_object_id` 且不含 acceptance timestamp；跨表/跨对象、两表同时命中或任一持久语义分歧拒绝，迁移/运维/repository/SQL 权限不得形成旁路。
- receipt 的 `manifest_digest` 对两种 MCP artifact kind 都恰为数据库当前已批准 connector `McpManifestV1` canonical JCS digest，并等于 subject `manifest_version_id` 行；绝不是 CAB 内 `McpLocalArtifactManifestV1` digest。inner artifact manifest 只由 `package_digest=SHA-256(exact package.cab)` 唯一绑定，安装器与 plugin-host 每次从 CAB 原文重算其 JCS/CMS/roster；不另造第二个 receipt/DB manifest digest。
- 两个 exchange operation 只用独立 strict `McpExchangeChunkStreamV1` / `McpExchangeChunkStreamFrameV1`；frame 闭集恰为请求方向 `RequestBegin|RequestChunk|RequestEnd`、唯一授权帧 `DispatchAuthorized`、响应方向 `ResponseBegin|ResponseChunk|ResponseEnd` 与共享 `Abort|Ack` 九项。`McpExchangeRequestV1` 与 `RequestBegin` 都带同一 `invocation_id`，wire 不带 wall-clock deadline 字段；两方向使用不同 stream id/sequence，response 只可用 `request_stream_id` 绑定已获有效授权的请求，End 与 Ack 均使用 `next_sequence_no`。receiver 从收到 RequestBegin 起以本机单调时钟计算唯一 30 秒绝对时限，覆盖校验、rate reservation、等待授权、dispatch 和响应传完，任何帧都不能重置。不得复用阶段 3 的 `BoundedChunkStreamV1`、其 10/30/3600 秒档位或大文件恢复语义，不落盘、不跨连接恢复。
- Chunk 后只接受同 stream/next sequence 的 `Ack(CONTINUE)`；只验证 raw terminal length/sequence/SHA-256 的 ResponseEnd 后只接受 `Ack(COMPLETE)`；Abort 后恰回当前 next sequence 的 `Ack(ABORTED)` 并关闭。Begin 与 `DispatchAuthorized` 均无 ACK，任一错态至多发送一个分类 Abort、清零并关闭，不发第二 Abort/Ack。abort 闭集恰为 `CLIENT_DISCONNECT|DEADLINE|SIZE_LIMIT|HASH_MISMATCH|PROTOCOL_ERROR|RATE_LIMIT|AUDIT_UNAVAILABLE`。integration-gateway/plugin-host 保持 0 DB，不校验或猜测 current connector；receiver 只在 RequestEnd 后完成 length/digest/signature/trust/materialization/schema 校验并取得 global→connector permits、成功 reserve rate，才以 RequestEnd `COMPLETE` 表示“已验证且已计 rate、仍零 dispatch”。caller 在持有下述共享状态锁的同一专用 DB connection 上最终重读 current ENABLED/唯一 ACTIVE manifest digest/identity/authz/binding，独立提交确定性 ATTEMPT，成功才发送 exact `DispatchAuthorized{request_stream_id,attempt_event_id}`；receiver 核 event id 等于冻结 UUIDv5 公式后恰 dispatch 一次。ATTEMPT 失败发送 `AUDIT_UNAVAILABLE` Abort、零 dispatch且 rate 不退；COMPLETE 后授权前断开同样零 dispatch。response chunks 只承载 external/local child 产生的 exact 单一 terminal JSON-RPC bytes，最大 8388608，不序列化 `McpExchangeReplyV1` wrapper；SSE decoded body 恰为单 event，固定 framing 23 bytes、总上限 8388631。caller 收到 ResponseEnd COMPLETE 后才 size-first strict parse JSON/schema/field；失败写 terminal completion，但不撤销 COMPLETE、不退款、不重放。超 terminal/SSE 字节返回 `MCP.PAYLOAD.TOO_LARGE`，只有大小合法后的 JSON/schema/字段错误才返回 `MCP.RESPONSE.SCHEMA_INVALID`。
- 每 connector `max_calls_per_minute=60` 固定为无 burst 的进程内 60 秒单调时钟 sliding window。INBOUND 唯一顺序是 identity/proof 语法→ids→caller completion slot→global permit→connector permit→core rate reserve→counter UPDATE→当前事实/binding/authz→ATTEMPT→dispatch；counter UPDATE 失败才原子移除 rate，counter 成功后任何失败均不退。受理 UPDATE 可在 `max_calls=1` 的首个请求中把 grant 同语句置为 CONSUMED；该请求凭此次原子受理结果继续当前事实/binding/authz 与 dispatch，任何下游 ACTIVE 自检不得反向拒绝它，后续请求才因非 ACTIVE 失败。OUTBOUND 唯一顺序是 caller identity→ids→caller completion slot→caller 专用 DB connection 取得 connector-keyed session advisory shared lock并首次重读 current ENABLED/唯一 ACTIVE manifest digest/identity/authz/binding→receiver global/connector permits→receiver rate reserve→RequestEnd COMPLETE→caller 在同 connection/lock 内最终重读→caller ATTEMPT commit→`DispatchAuthorized`→receiver dispatch→terminal completion→释放 shared lock；rate 成功后 ATTEMPT/授权/外部/response 失败也不退。lock key 恰为 `hashtextextended(lower(connector_id::text),5568499270196608077)`；enable/disable/revoke 与 ACTIVE manifest 切换在同 key 上取得 transaction advisory exclusive lock并重读 row_version 后才变更。exclusive 变更等待最长 30 秒的已 dispatch 调用终态，提交后不可能再有旧状态 dispatch；caller crash 由 DB connection close 释放 session lock，hash collision 只增加串行。首次锁/重读失败已有 completion slot但零 receiver permit/rate/ATTEMPT/dispatch。core/integration-gateway/plugin-host 分别是 inbound/remote/local 唯一 rate owner，冷启动或 limiter 状态丢失先灌入 60 个 synthetic current timestamps，冷却 60 秒，不能按 caller 分摊或重启突发。

- MCP audit namespace 固定 `3f9b8e44-78a5-5ff0-8fc9-6ad25a8a5c55`，object type 固定 `platform.mcp.invocation`，object id 为 caller 生成的 UUIDv7 invocation id；attempt/completion event id 使用 F-55 固定 UUIDv5 公式。ATTEMPT/COMPLETION 的 strict `after` 公共字段恰为 `schema_version,phase,invocation_id,direction,transport,connector_id,manifest_version_id,method,binding_digest,decoded_name_sha256,request_schema_code,request_schema_version,request_payload_sha256,input_field_codes,request_bytes,request_id,trace_id`，COMPLETION 再恰有 `response_schema_code,response_schema_version,response_payload_sha256,output_field_codes,outcome,stable_code,duration_ms,response_bytes`，`before` 固定空。identity 后 name/URI 未规范解码时 name/binding/request-schema 为 NULL 且 input `[]`；四个无具名方法通过 transport schema 后同形；tools/call/resources/read 规范解码但 binding 未解析/不可见时只有 decoded-name hash；tools/call binding 后另有 binding digest/request schema/input codes，resources/read binding 后只有 binding digest且 schema NULL/input `[]`。ATTEMPT 只允许四个无具名方法已过 transport schema或两个具名方法已落在 binding-resolved 形状，绝无半解析形状。
