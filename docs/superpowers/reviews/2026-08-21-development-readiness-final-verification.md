## 3. 原 9 条未决与 F-10 内部矛盾的关闭结果

F-49 留下的 9 条财务一致性问题已由 F-50 批准并完成权威回写，实际未决为 0：

| 编号 | 已冻结的唯一结论 |

| 1 | 退款或返款对原核销追加 `RELEASE`，不是新的正向核销，也不增加第六种资金冲正原因 |
| 2 | 红冲释放按有效未核销余额计算，多关系固定按 LIFO 分摊 |

| 6 | 进项发票同样支持多行、多税率和逐行红冲 |

## 4. 范围与架构闭合

- 首版业务范围覆盖客户、投诉与售后工单、订单、合同关键资料/收款/附件，以及销售、采购、库存、财务、服务、项目、资产、报表和运维联动。
- 客户数据采用同一客户数据库，通过法人标识、行级权限和独立密钥域隔离；数据库只交付自建 PostgreSQL 16，也允许连接客户既有受控能力，但不依赖托管数据库或云 KMS。
- 首版服务器形态是单台 Windows Server 2022，可部署在客户控制的物理服务器或客户控制的国内 IaaS 虚机；同一台服务器运行全部服务和数据库。首版不承诺高可用。
- Windows、macOS、iOS、Android 使用共享 Rust 核心并保持端能力矩阵一致；ServerAdmin 是独立受控管理端。
- 本地只读 AI、受控双向 MCP、签名模块包、WASM 扩展和经审批的受控容器插件均有明确边界。许可证与模块包、AI、MCP 和 ServerAdmin/云 carrier 的实施入口分别为：[F-56 实施计划](../plans/2026-08-22-license-module-package-implementation.md)、[阶段 13c](../plans/2026-08-10-first-release-dev-plan/13c-local-ai-mcp-server-admin.md)、[本地 AI 计划](../plans/2026-08-22-local-ai-implementation.md)、[MCP 计划](../plans/2026-08-22-mcp-extension-implementation.md)、[ServerAdmin 与云 carrier 计划](../plans/2026-08-22-server-admin-cloud-carrier-implementation.md)。

### 5.4 安全与勒索风险

[仓库级威胁模型](../../threat-model.md)已覆盖身份越权、跨法人数据泄漏、插件与 MCP 扩权、供应链、本地 AI、云控制面、审计破坏、备份破坏和勒索攻击路径。首版明确要求异机/异介质备份、恢复材料隔离、恢复演练、最小权限、应用级只追加/哈希/签名证据和失败关闭。系统机密终态也已闭合：数据 KMS common master 不与六个服务共享，每 recipient 使用独立 DPAPI KEK 或 HSM object；Stage 1 明文只经签名迁移工具进入隔离/最终处置，任一残留阻断发布。零 KMS 集成凭据只由 SCM 加载 profile 后的目标服务 current token 写入 WinCred。

许可证和模块供应链同样闭合为离线失败关闭：配置包外层签名与业务 artifact 内层 CMS 必须分别通过，信任包路径、摘要、ACL 和维护窗口轮换均固定；模块包只允许声明统一签名产品内已编译模块的安装、启用、停用、升级或显式版本回退，不能携带可执行代码、SQL、脚本、容器、路径或 URL。跨进程模块变更通过数据库 advisory lock 排空在途；停用保留全部数据和历史证据。

发行签名人的唯一授权源已经收束为已验签部署清单中的 signed signer roster；本地配置只能留空或作逐项完全相等的漂移断言，不能增删信任人。可信时间 checkpoint 使用 240 秒 UTC slot 的 append-only 首行语义，服务持续运行证据中相邻成功值超过 300 秒即发布失败。fresh-production 首装的法人、两名管理员、权限、37 条默认审批链、PROVISIONING 密钥域、不可变初始激活快照、首张许可、审计与 unsigned receipt 也已形成单一可重算证据图；后续合法密钥轮换不会反向破坏初始证据。

最后独立交叉审查还逐项关闭了五类实现歧义：initial-governance、可信时间 checkpoint 与 CRL-revoked 模块停用三种审计均冻结完整 envelope；recovery batch 固定先写 recovery event、再写且最后写 accepted event；配置发布总锁序固定为 license exclusive → 仅 ordinary execute 的 mutex → package/order/item → module；订阅许可从 `valid_to-60 days` 当日开始进入 EXPIRING_SOON，不留一天空档；已安装模块的 min 版本必填而 max 可为 null（无上界）；fresh-bootstrap 的八张身份安全表必须全部为零行。上述字段、顺序与边界均进入 Stage 14 逐列负例校验，不再依赖实现默认值。

同时保留以下真实剩余风险，不把设计控制写成绝对安全：

- 单服务器没有高可用，主机或云区域故障会造成停机，恢复依赖服务器之外的有效备份。
- 首版没有经认证的 WORM 后端，也不承诺真正物理气隙；掌握操作系统、存储或备份管理最高权限的人仍可能绕过应用控制。
- 客户 IaaS 控制面、最高权限账号、备份落点和密钥恢复材料是否真正分离，必须由具体部署证据证明。
- 防勒索成败最终取决于“攻击者不能同时控制生产、备份与恢复材料”以及恢复演练真实通过，不能只凭产品功能清单判断。

## 6. 不属于设计未决、但仍会阻止启用或发布的证据

以下项目已有固定判据和失败处置，因此不是开发前需要再选择的方案；证据未取得时，相应能力保持 `UNVERIFIED`、禁用或阻止发布：

- Windows Server 2022 实机上的资源、DACL、Job Object、服务身份、签名、网络和恢复验证。
